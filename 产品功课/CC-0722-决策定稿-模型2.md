## 一、Cashback 消费返现（CC-0722-01）

**原始需求**〔新需求·确认〕：给信用卡加消费返现，**既能抵扣账单、又能提现**，账单重点展示。

**背景 — 提现在本平台怎么实现**〔机制〕：平台已有统一"提现"标准 + 一个与 cashback 同构的现成实现，cashback 提现**直接复用、几乎零新造**：
- 统一提币交互标准（最低额 + 网络费单笔固定扣减 + 到账实时预览 + 地址按网络校验）：`CC-CHANGE-0715.md §8`（CC-0715-06，约 `:550-596`）
- 同构实现「超额还款提币 CC-FEE-04」（提现订单表 `overpayment_wallet_withdrawal` + 费用配置表 `withdrawal_fee_config`）：`CC_FEE_REQUIREMENTS.md:335-405`（数据模型 `:355-384`）

### 决策 1.1 · 返现计算与发放【③ PM 拍板】

- **结论**：档位 2%/2.5%/3% + cap 500/1000/1500〔新需求·mentor 提供，公式见需求总参考 A-3〕，按**开卡年**、达档**全量适用**、边界**含等于**、仅计**已清算**消费；返现随**各用户账单出账日**计算，以 USDT 发放进用户的**可提现 USDT 余额**。
- **竞品分析**：加密卡返现主流即"独立可支配余额"——Nexo 双币独立余额可上链/换法币（[Nexo KB](https://nexo.how/kb/what-crypto-rewards-will-i-get-with-my-nexo-card/)）、Crypto.com CRO 进独立钱包（[条款 PDF](https://crypto.com/document/us_credit_card)）、Wirex 即时发到可支配余额（[Wirex 官方](https://help.wirexapp.com/article/wirexs-cryptobacktm-rewards-explained-1346)）；随账单出账是传统卡惯例（[Chase](https://www.chase.com/freedomflex/rewardsagreement) / [Discover](https://www.discover.com/credit-cards/cash-back/cashback-bonus.html)）。
- **依据**：档位/cap/开卡年/全量/含等于〔新需求·mentor 提供 + 用户拍板〕；只认已清算、递延出账日算〔新需求·确认〕。
- **用户故事**：C 端拿到"自己挣的钱"、可自主处置；业务随出账 job 批量算；后台复用既有零点批处理、不增人工。
- **影响**：清算终态 = 平台收到消费 Webhook〔机制 `prd-xaue-credit-card.md:11` `cardTransactionSuccess`〕；各用户出账分散 → 返现入账分散全月、现金流平滑。

### 决策 1.2 · 余额三能力（抵扣 / 提现 / 留存）【③ PM 拍板】

- **结论**：返现进**可提现 USDT 余额**，**默认自动抵扣当期账单应还**（减少还款、账单页重点展示），用户可改为**提现**或**留存**——三能力并存、默认抵扣可改（方案 A，2026-07-24 定）。三能力落地见下 ①②③。
- **① 抵扣账单落地**〔机制〕：账单生成合计式已有"减项"位置（`ch5-billing.md:449-459` Step 7，其中 `:453` `- period_refund_amount` 即退款减项）——cashback 抵扣可作**同类账单减项**减少 `total_amount_due`；或经还款冲抵路径处理（`ch5-billing.md:506-523` 8 优先级）。
- **② 提现落地**〔机制〕：复用 CC-FEE-04 → 币安式提现页（`CC-CHANGE-0715.md §8`）→ 最低提现额校验（`CC_FEE_REQUIREMENTS.md:62-63`）→ **目标地址命中白名单**（CC-0722-04）→ **过 AML**（CC-0722-03）→ 扣网络费（计入平台运营收入 `CC-CHANGE-0715.md:565`）→ 出金走平台钱包（`ch11-wallets.md:13` settlement/hot_buffer，非金库合约）→ 落 `overpayment_wallet_withdrawal`（`CC_FEE_REQUIREMENTS.md:355-373`）。
- **③ 提现收费**〔机制〕：与超额还款提币一致收网络费 + 最低额（`CC_FEE_REQUIREMENTS.md:62-63`）——防高频小额薅 gas、口径统一。
- **默认动作【已定 · 方案 A · 2026-07-24】**〔新需求·确认〕：返现到账后**默认自动抵扣当期账单应还**（减少还款、账单重点展示）；用户可在设置改为"不抵扣、留在可提现余额"，供留存或提现。
- **竞品分析**：竞品返现多为独立余额、可提现/换币（Nexo/Wirex 同上）；账单抵扣是我方结合原始需求的设计。
- **⚠️ 影响-资金池（金融视角必看）**：提现让返现成为**即时可提现负债**（用户随时提走），需备付金覆盖。缓解现成：最低提现额 + 网络费 + 白名单 48h 冷静期抑制高频小额；年 cap（500/1000/1500）封顶总负债规模。
- **影响-后台**：抵扣复用账单生成/冲抵；提现复用 CC-FEE-04 审计列表 + 费用配置，无新增后台模块。

## 二、XAUT Staking Reward（CC-0722-02）

**背景 — 两条独立路径**〔机制，纠正上一稿"串联双层"误解〕：
```
用户持有 XAUT
 ├ 路径 1（Shop Stake）：XAUT → XAUEVault 合约 → 铸造 XAUE + Stake APY 收益
 │    prd-xaue-stake.md:51 stake(xautAmount)→Staked；:11 质押比 1 XAUT : 1000 XAUE
 └ 路径 2（信用卡）：XAUT → Collateral Vault 金库合约 → 信用卡额度 + Staking Reward（较低 APY）
      prd-xaue-credit-card.md:5,55 质押物锁入 Collateral Vault；ch3-credit-line.md:53 额度公式
```
两条路径**独立并列**、用户择一。路径 2 的抵押品本为零息，本需求给它一个独立低 APY 激励用信用卡。

### 决策 2.1 · APY 数值【③ PM 拍板，竞品定锚】✅ 0.4%

- **结论**〔新需求·确认〕：**APY = 0.4%/年**，**低于路径 1 Stake APY**（路径 1 APY 为变动值、原始 PRD **不写死** —— `prd-xaue-stake.md:72,138` 仅"估算 APY / 历史 APY 折线图"字段）。文案须 "up to 0.4% / variable / subject to change"。
- **竞品分析**（正确的锚 = 抵押品"被占用作担保"期间收益率）：wstETH 抵押进 Aave supply APY = 0.00%（[Aavescan](https://aavescan.com/ethereum-v3/wsteth)）；Compound V3 官方"抵押品不生息"（[docs](https://docs.compound.finance/collateral-and-borrowing/)）；CeFi 主流零息（Crypto.com [help](https://help.crypto.com/en/articles/2996965-crypto-earn-how-does-it-work) / YouHodler [help](https://help.youhodler.com/en/articles/7734037-loan-f-a-q) / Ledn [borrowing](https://www.ledn.io/borrowing)）。→ 市场担保占用收益系统性≈0%。
- **依据**：APY 数值 0.4%〔新需求·确认〕；"低于纯质押（路径 1）"〔新需求·mentor A2-6，需求总参考 B-staking-6〕。
- **为什么这样定**：市场担保占用收益≈0%，任何正 APY 本质是**平台激励补贴**——0.4% 高于地板 0%（有感知）、低于路径 1 Stake APY（防套利、成本可控）；定性"激励奖励"而非"资产收益"、证券属性更安全。
- **影响**：补贴成本 = APY × 质押量、可测算；无资金池波动；并入出账 job 自动算。

### 决策 2.2 · 覆盖币种 / 计息基数 / 发放【③ PM 拍板】

- **结论**〔新需求·确认〕：覆盖币种 = **XAUT**；计息基数 = 信用卡质押的 **XAUT 数量**（按持仓时长加权）；随**各用户账单出账日**发放；**USDT 记账**。
- **币种说明**：XAUT↔XAUE 为 **1:1000 固定汇率**〔机制 `prd-xaue-stake.md:11`〕，额度计算上等价，故与原始 PRD 主 PRD:26 的"质押品 XAUE"表述**等价无实质差异**；本决策以 2026-07-24 与 mentor 确认的 **XAUT** 为准。
- **竞品分析**：Kraken 用独立会计科目 `type=earn`+`subtype=reward` 记收益（[Kraken ledger](https://support.kraken.com/articles/360001169383-how-to-interpret-ledger-history-fields)），accrue daily / paid weekly（[Opt-In Rewards](https://support.kraken.com/articles/360044886311-overview-of-opt-in-rewards-on-kraken)）；我方借鉴"独立记账科目"，发放改与账单同步。
- **⚠️ 不涨额度**〔机制〕：reward 用 **USDT 发放、不增发质押**，故质押 XAUT 数量不变、**额度不受影响**——额度公式 `credit_limit = collateral_value × 0.6 + overpayment`（`ch3-credit-line.md:54`），只随质押品估值与 LTV，与 reward 无关。
- **依据**：币种/基数/发放〔新需求·确认〕；不涨额度〔机制 `ch3:54`〕。
- **影响**：无资金池冲击；后台并入出账 job、自动化。

### 决策 2.3 · 清算/解押/销卡残值结算【③ PM 拍板】✅ 平台全吃

- **结论**〔新需求·确认〕：清算/解押/销卡时，**"已计提未发放"的 reward 平台全吃、不向用户结算**（推翻上一稿"按日折算发用户"）。
- **名词（大白话）**：**平仓线** = 抵押率（已用额度÷质押品现值）到 **LTV≥91%** 强制清算〔机制 `ch3-credit-line.md:108`、`prd-xaue-credit-card.md:61`；三级档位 NORMAL/WARN1/WARN2/LIQUIDATION `ch3:105-108`〕，**非本次新增**。清算残值收益 = 清算那刻这部分 XAUT 还有一小笔"按天算好、没到发放日"的 reward。
- **为什么这样定**：简化结算逻辑、金额小、清算本属违约场景；已与 mentor 权衡确定。
- **⚠️ push back（保留备选，供审阅斟酌）**：清算时没收已计提收益可能被用户视为"趁火打劫"→ 招投诉；若想留缓冲，可折中"仅**强制清算**全吃，**主动解押/销卡**仍按日折算发给用户"。当前按"全吃"落地。
- **影响**：省一处结算逻辑；后台三种终止路径不加发放步骤。

## 三、白名单地址 + 入金 AML（CC-0722-03 / 04）

**原始需求**〔新需求·确认〕：接 WaaS AML 查地址；命中禁归集并提示；出金登记白名单；入金因 web3 属性不限制；仅信用卡端。

### 决策 3.1 · 隔离资金终局处置【③ PM 拍板】✅ 采纳

- **结论**〔新需求·确认〕：命中黑灰的资金 **冻结隔离 + 合规人工审查 + 按辖区处置**（司法冻结/SAR 上报/明确误判经复核解冻），**绝不无条件退回**；隔离导致还款失败→逾期的，**误伤经核实豁免罚息**（隐藏需求）。
- **竞品分析**：Cobo Screening 命中 inbound = Funds will be frozen（[Cobo 文档](https://manuals.cobo.com/en/apps/screening/introduction)）；Binance 走 withdrawal under review 人工审查（[Binance FAQ](https://www.binance.com/en/support/faq/360038583951)）；FATF Rec.16 要求冻结+核验、不主动退回（[FATF](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/update-Recommendation-16-payment-transparency-june-2025.html)，官方页·反爬）。
- **为什么**（否决"退回原地址"）：退回疑似脏钱可能构成协助转移赃款/违反冻结义务——合规红线。
- **影响**〔机制〕：命中资金进独立隔离钱包——`ch11-wallets.md:13` 现为 **3 平台钱包 + 抵押品金库合约**，隔离钱包应作**第 4 类平台钱包**加 `isolation` 枚举（非"第 5 个"）；合规人工审查是新增后台工作量。

### 决策 3.2 · WaaS AML 对接【② 竞品答 + 待研发对接】

- **结论**〔新需求·确认〕：接入 WaaS AML（不自建）；数据模型/接口遵循供应商官方 Screening API；**具体对接细节交研发那边对接**。
- **竞品分析**：Cobo Screening 集成 CipherOwl/Elliptic/Chainalysis，充值查 from、提现查 to，四档处置（Approve/Alert/Reject/Manual Review）——[Cobo 文档](https://manuals.cobo.com/en/apps/screening/introduction)。
- **待办**：向服务商索取官方 Screening API 文档，按其 schema 对齐。
- **⚠️ 文档归属更正**〔机制〕：信用卡入金 AML 是**新建文档**——`credit-card/S4-AML.md` 不存在；`gift-card/prd-s4.md` 是礼品卡 AML（不适用信用卡）；信用卡现有仅 Sumsub 开卡查人（`prd-xaue-credit-card.md:5` KYC 走 Sumsub），入金来源地址 AML 为全新维度。

### 决策 4.1 · 出金白名单冷静期 / 上限 / 兜底【③ PM 拍板】✅

- **结论**〔新需求·确认〕：**强制白名单**（出金只能提到已登记且生效地址）+ **仅新增地址 48h 冷静期**（删除即时生效）+ 地址上限暂不设 + 邮件确认 & 2FA + **允许删光重登恢复**。
- **机制依据**〔机制〕：出金 `destination_whitelist_id` "必须命中白名单（除非临时审批）"（`ch11-wallets.md:187`）——白名单是既有出金字段，本需求将其设为**强制**。
- **竞品分析**：新地址冷静期 Coinbase 48h（[Coinbase](https://help.coinbase.com/en/coinbase/managing-my-account/other/address-book-allowlist)，官方页·反爬）/ Bybit 24h / Binance 可配 24-72h + 上限 200（[Binance](https://www.binance.com/en/support/faq/1d08944f103b4fc78d3519913b600086)）。竞品"对称关闭冷静期"针对可选白名单，我方强制白名单不需要。
- **为什么**：新地址冷静期防盗号加址立即提；强制白名单下删地址只缩小可提范围，故删除不需冷静期；删光可重登恢复更尊重用户自主。
- **影响**：无资金池影响；后台无新增人工。**cashback 提现的目标地址走此同一套白名单**（见 1.2）。

### 决策 4.2 · 白名单是否需人工审批【③ PM 拍板】✅ 始终自动

- **结论**〔新需求·确认〕：**始终自动、无人工**——登记地址过 WaaS AML 自动检测，通过即进 48h 冷静期，届满自动生效。
- **竞品分析**：Binance/Coinbase 白名单均自动 AML 通过即生效、无人工（[Binance FAQ](https://www.binance.com/en/support/faq/1d08944f103b4fc78d3519913b600086)）。
- **为什么**：三层安全（AML 自动检测 + 48h 冷静期 + 强制白名单）已足够，无需人工队列。
- **影响**：无资金池影响；后台零人工审核。

> **🔑 与 Cashback 提现的联动**：CC-0722-04 白名单 + CC-0722-03 AML 同时服务于"cashback 提现出金"——提现目标地址走同一套白名单登记 + AML 检测，无需为 cashback 单造出金风控。
