## 一、Cashback 消费返现（CC-0722-01）

**原始需求**：给信用卡加消费返现，在账单里抵扣、重点展示。

**三层速览**：① 定档位公式 2%/2.5%/3% + cap 500/1000/1500、按开卡年、USDT 账单抵扣、只认已清算、递延到出账算 → ② 竞品答"按清算后交易算、随账单出账"是传统卡惯例、"提现"是笔误 → ③ PM 拍板返现>应还时结转下期。

### 决策 1.1 · 返现到账时点【② 竞品答】✅（有提现功能）

- **结论**：随**各用户账单出账日**统一计算、账单内抵扣（还款日用户自设 1–28，各人出账时点不同）。
- **竞品分析**：
  - 传统卡 statement-close：Chase 返现"at the close of each monthly billing cycle"、按 posted − returns/refunds —— [Chase 返现协议](https://www.chase.com/freedomflex/rewardsagreement)（跳转 [PDF](https://asset.chase.com/content/dam/card/rulesregulations/en/RPA0534_Web.pdf)）
  - Citi Double Cash 两段式（1% 消费 + 1% 还款）—— [Citi 官方](https://www.citi.com/credit-cards/credit-card-rewards/citi-double-cash-credit-card-benefits)
  - Discover 仅 processed 交易"only when they're processed" —— [Discover Cashback Bonus](https://www.discover.com/credit-cards/cash-back/cashback-bonus.html)
  - Nexo settle 后发放 —— [Nexo 博客](https://nexo.com/blog/switch-to-shopping-mode-and-get-crypto-cashback)；Crypto.com CRO 最长 2 个账单周期 —— [美国卡条款 PDF](https://crypto.com/document/us_credit_card)
- **用户故事**：C 端要可预期的到账节奏；业务上账单出账即清算终态；后台随账单算最简、免 clawback。
- **为什么这样定**：全行业主流就是 statement-close，且账单出账时该周期交易已清算完成——对齐惯例又最简，无需处理未清算交易的返现回滚。
- **影响**：清算时点 = 平台收到 `cardTransactionSuccess` Webhook；各用户出账分散在 1–28 号 → 返现入账分散全月、资金池现金流**更平滑**；后台复用 CC-0715-07 已有的零点批处理、**不增人工**。

### 决策 1.2 · 返现 > 本期应还的剩余处理【③ PM 拍板】✅（考虑到提现功能的存在，这一点也要修改）

- **结论**：剩余返现**结转下期账单继续抵扣**。
- **竞品分析**：竞品普遍把返现做成**独立余额、不冲账单**（故无"返现>应还"问题）——Nexo 双币独立余额可上链/换法币（[Nexo KB](https://nexo.how/kb/what-crypto-rewards-will-i-get-with-my-nexo-card/)）、Crypto.com CRO 进独立钱包（[条款 PDF](https://crypto.com/document/us_credit_card)）、Wirex 即时发 WXT 到可支配余额（[Wirex 官方](https://help.wirexapp.com/article/wirexs-cryptobacktm-rewards-explained-1346)）。我方"账单内抵扣"是差异化设计，须自定剩余规则。
- **用户故事**：C 端要返现不蒸发、可累积；业务/资金池——无提现则剩余只是账面递延（结转），不产生即时可提现负债、不冲击备付金；后台结转最简。
- **为什么这样定**：无提现功能 → 排除"转可提现"；三视角一致指向结转（不蒸发 + 无资金池冲击 + 后台最简）。
- **影响**：账本挂 carry-over 字段、下期优先抵扣；无提现负债、资金池无压力；后台零新增人工。

## 二、XAUT Staking Reward（CC-0722-02）

**原始需求**：给信用卡质押的 XAUE 一个独立 APY 激励（低于纯质押），用记账流水让用户感知。

**关键背景（双层质押）**：第一层 XAUT 质押入 Vault 得 XAUE，**已生息 ~4%**（汇率增值）；第二层 XAUE 再质押进信用卡换额度，**当前零息**。本需求给第二层一个独立 APY，激励用户用信用卡。

**三层速览**：① 定独立 APY、必须低于第一层 ~4%、记账流水形式 → ② 竞品答"抵押品担保占用期市场收益≈0%" → ③ PM 拍板 APY 1%、基数=信用卡质押 XAUE、随出账日 USDT 发、不涨额度、清算按日折算。

### 决策 2.1 · APY 数值【③ PM 拍板，竞品定锚】✅ 1%（现在激励已经确定了：0.4%）

- **结论**：**APY = 1.0%/年**（自主决定）。文案须 "up to 1% / variable / subject to change"。
- **竞品分析**（正确的锚 = 抵押品"被占用作担保"期间的收益率，不是自由持有）：
  - **wstETH 抵押进 Aave supply APY = 0.00%**（最同构样本）—— [Aavescan wstETH](https://aavescan.com/ethereum-v3/wsteth)（底层 staking ~2.2% 是另一回事，Lido 官方证实：[help.lido.fi](https://help.lido.fi/en/articles/8459223-guide-how-to-use-steth-wsteth-on-aave)）
  - **Compound V3 官方明文"抵押品不生息"** —— [docs.compound.finance](https://docs.compound.finance/collateral-and-borrowing/)
  - CeFi 主流零息：Crypto.com（须改放 Earn 才生息，[help.crypto.com](https://help.crypto.com/en/articles/2996965-crypto-earn-how-does-it-work)）、YouHodler（"collateral does not earn reward"，[help.youhodler.com](https://help.youhodler.com/en/articles/7734037-loan-f-a-q)）、Ledn（收益归平台，[ledn.io/borrowing](https://www.ledn.io/borrowing)）
  - 例外（少数继续生息）：Binance Flexible Loan 抵押品零折扣继续赚（[Binance FAQ](https://www.binance.com/en/support/faq/what-is-binance-flexible-loan-and-frequently-asked-questions-1c9dddb774054983992b8977ae36577a)）、Nexo 仅 NEXO/NETH 例外（[Nexo](https://nexo.com/en-us/borrow)）
  - 理论背书：rehypothecation rebate / securities lending rebate / collateral haircut（[Longbridge](https://longbridge.com/en/learn/rehypothecation-100199) / [Sharegain](https://sharegain.com/securities-lending-explained/rebate-rate/) / [ISLA](https://www.islagroup.org/understanding-collateral/)）
- **用户故事**：C 端从"零"到 1% 已是质变、有感知；业务补贴成本最省（资金是借来的）；风控与第一层 4% 差距大、最防套利。
- **为什么这样定**：市场担保占用收益系统性≈0%，所以任何正 APY 本质是**平台激励补贴**（非市场收益）——1% 明显高于地板 0%（用户有感知）、远低于第一层 4%（防套利、成本可控）；且定性为"激励奖励"而非"资产收益"，**证券属性更安全**。
- **影响**：补贴成本受 APY×质押量决定、可测算；无资金池波动；后台并入出账 job 自动算。

### 决策 2.2 · 计息基数 / 发放【③ PM 拍板】✅

- **结论**：计息基数 = 信用卡质押的 XAUT 数量（按持仓时长加权）；随**各用户账单出账日**发放；**USDT 记账**。
- **竞品分析**：Kraken 用独立会计科目 `type=earn` + `subtype=reward` 记收益（可单独查询/导出/计税）—— [Kraken ledger 字段](https://support.kraken.com/articles/360001169383-how-to-interpret-ledger-history-fields)；其 Opt-In Rewards 为 accrue daily / paid weekly / in-kind —— [Kraken Opt-In Rewards](https://support.kraken.com/articles/360044886311-overview-of-opt-in-rewards-on-kraken)。我方借鉴其"独立记账科目"，但发放改为与账单同步（强化"用信用卡"的综合感知）。
- **用户故事**：C 端随出账日和 cashback 一起看到"用信用卡的综合好处"、感知最强；业务 USDT 记账避免脱锚；后台与出账 job 合并、少一条流程。
- **为什么这样定**：我认为意图是"激励用信用卡"，所以基数用"为换额度而质押的 XAUE"、发放与账单绑定最贴合；USDT 记账最稳。
- **⚠️ 关键澄清（不涨额度）**：reward 用 **USDT 发放、不增发质押 XAUE**，故质押账户 XAUE 数量不因计息上升，**信用额度不随 reward 变化**（额度只随质押 XAUE 数量 × XAUE 市场价 × LTV）。
- **影响**：无资金池冲击；后台并入出账、自动化。

### ~~决策 2.3 · 清算/解押/销卡时未发收益结算【③ PM 拍板】✅~~（这一点不考虑，残值全吃）

- **结论**：**按日折算发放至终止时点**——清算/解押/销卡结算环节结清"已计提未发放"的 reward。
- **名词（大白话）**：**平仓线** = 现有 PRD §3 风控，抵押率（已用额度÷质押品现值）升到 **91%** 就强制清算（把质押 XAUE 卖去还债），三级预警 72/81/91%，**非本次新增**。**清算残值收益** = 清算那刻这部分被卖的 XAUT 还有一小笔"按天算好、没到发放日"的 reward，本决策定它归用户。
- **竞品分析**：纯 earn 产品无"强制清算"场景、**无直接先例**（清算是信用卡质押品特有）；最近类比 = wstETH 抵押被平仓时底层 staking 已累积部分照结算（逻辑同源，[help.lido.fi](https://help.lido.fi/en/articles/8459223-guide-how-to-use-steth-wsteth-on-aave)）。
- **用户故事**：C 端——清算是高压力事件，没收已计提收益会被视为趁火打劫 → 强投诉；业务——按日折算金额小、不占质押品、不阻碍清算；后台——最公平、申诉最少。
- **为什么这样定**：无竞品先例 → 按第一性原则 + 用户故事推导，按日折算最公平、最少客诉、不阻碍清算变现。
- **影响**：收益是账本负债、不占质押品，清算变现不受影响；后台在三种终止路径加结算步骤。

## 三、白名单地址 + 入金 AML（CC-0722-03 / 04）

**原始需求**：接 WaaS AML 查地址；命中禁止归集并提示；出金登记白名单；入金因 web3 属性不限制。

**三层速览**：① 定接 WaaS（不自建）、黑灰以 WaaS 阈值、命中禁归集+双端提示、出金登记白名单入金不限、仅信用卡端 → ② 竞品答"命中=冻结+审查+按辖区上报（绝不退回）"、冷静期 48h、接口遵循 Cobo → ③ PM 拍板隔离处置采纳、误伤豁免、强制白名单+仅新增冷静期、始终自动、黑钱污染换址。

### 决策 3.1 · 隔离资金终局处置【③ PM 拍板】✅ 采纳

- **结论**：命中黑灰的资金 **冻结隔离 + 合规人工审查 + 按辖区处置**（司法冻结/SAR 上报/明确误判经复核解冻），**绝不无条件退回**；【隔离导致还款失败→逾期的，**误伤经核实豁免罚息**。（隐藏需求）】
- **竞品分析**：Cobo Screening 命中 inbound = **Funds will be frozen**（Reject 档冻结，非退回）—— [Cobo Screening 文档](https://manuals.cobo.com/en/apps/screening/introduction)；Binance 命中走 withdrawal under review 人工审查 —— [Binance FAQ](https://www.binance.com/en/support/faq/360038583951)；FATF Travel Rule（Rec.16）要求冻结+采集核验、不主动退回 —— [FATF Rec.16（2025）](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/update-Recommendation-16-payment-transparency-june-2025.html)（官方页·反爬）。
- **用户故事**：C 端——可能误伤，要救济与申诉；业务——隔离资金绝不混入主池（防污染平台地址被连带标记）；合规后台——须留痕、可上报、按辖区处置。
- **为什么这样定**（否决"退回原地址"）：退回疑似脏钱可能构成协助转移赃款/违反冻结义务——这是合规红线；竞品与 FATF 通例都是冻结+调查+上报。
- **影响**：命中资金进独立隔离钱包（⚠️ 基线更正：ch11 v0.3 现为 **3 平台钱包 + 抵押品金库合约**，隔离钱包应作**第 4 类平台钱包**加 `isolation` 枚举，非原描述的"第 5 个"）；合规人工审查是新增后台工作量（关注点④最重一块）。

### 决策 3.2 · WaaS AML 对接【② 竞品答 + 待发 WaaS】（具体问题等研发那边对接）

- **结论**：数据模型/接口**遵循 Cobo 官方 Screening API、不自定**；具体对接清单待发 WaaS（Cobo 文档暂拿不到，先不阻塞）。
- **竞品分析**：Cobo Screening 集成 CipherOwl/Elliptic/Chainalysis，**充值查 from address、提现查 to address**，四档处置粒度（Approve/Alert/Reject/Manual Review）—— [Cobo Screening 文档](https://manuals.cobo.com/en/apps/screening/introduction)（背景 [Cobo WaaS](https://www.cobo.com/products/waas)）。
- **用户故事**：后台——接口对齐官方能省自建、四档处置直接可用；合规——Manual Review 档是防大规模误伤的关键。
- **为什么这样定**：AML 是专业能力，遵循 Cobo 官方 schema 比自定更稳、更快落地。
- **影响**：检测同步/异步时序影响用户端"充值到账"感知——是待向 Cobo 确认的关键项。
- **待办**：向服务商索取 Cobo 官方 Screening API 文档，按其 schema 对齐（7 项对接问题清单见 PRD §6）。
- **⚠️ 文档归属更正**：信用卡入金 AML 是**新建文档**——原描述的 `credit-card/S4-AML.md` 并不存在，`gift-card/prd-s4.md` 是礼品卡 AML（Chainalysis/下单查 sender/三档，不适用信用卡）；信用卡现有 AML 仅 Sumsub 开卡查人，入金来源地址 AML 为全新维度、与之并存。

### 决策 4.1 · 出金白名单冷静期 / 上限 / 兜底【③ PM 拍板】✅ 方案 A

- **结论**：**强制白名单**（出金只能提到已登记且生效的地址，无"关闭=任意提"）+ **仅新增地址 48h 冷静期**（删除即时生效）+ 地址上限 20（暂时没有上限） + 邮件确认&2FA + **允许删光重登恢复**。
- **竞品分析**：新地址冷静期 Coinbase **48h**（[Coinbase allowlist](https://help.coinbase.com/en/coinbase/managing-my-account/other/address-book-allowlist)，官方页·反爬）/ Bybit 24h（[Bybit](https://www.bybit.com/en/help-center/article/How-to-Manage-Your-Withdrawal-Address-Book)，官方页·反爬）/ Binance 可配 24/48/72h + 上限 200（[Binance 白名单 FAQ](https://www.binance.com/en/support/faq/1d08944f103b4fc78d3519913b600086)）。**注**：竞品的"对称关闭冷静期"是针对"可选白名单"设计，我方强制白名单不需要。
- **用户故事**：C 端安全 vs 便利（黄金卡地址不多，5 个够）；资金安全——新地址冷静期堵盗号后"加自己地址立即提"的窗口；后台——强制+单向冷静期逻辑最简。
- **为什么这样定**（#11/#12 修正）：新地址冷静期防盗号加址立即提；**强制白名单下删地址只会缩小可提范围、盗号者反而更提不出钱**，故删除不需冷静期（不抄竞品对称冷静期）。删光兜底：允许删到 0、资金不锁死，重新登记（走冷静期）即恢复——比"强制留 1 个"更尊重用户自主。
- **影响**：无资金池影响；后台无新增人工（自动检测）。

### 决策 4.2 · 白名单是否需人工审批【③ PM 拍板】✅ 始终自动

- **结论**：**始终自动、无人工审核**——登记地址过 Cobo AML 自动检测，通过即进 48h 冷静期，届满自动生效。
- **竞品分析**：Binance 白名单自动 AML 通过即生效、无人工（[Binance FAQ](https://www.binance.com/en/support/faq/1d08944f103b4fc78d3519913b600086)）；Coinbase 同样自动（48h 冷静期兜底，[Coinbase allowlist](https://help.coinbase.com/en/coinbase/managing-my-account/other/address-book-allowlist)，官方页·反爬）。
- **用户故事**：C 端要地址快速生效；后台——无人工队列、零负担；安全由"AML 自动检测 + 48h 冷静期 + 强制白名单"三层保证。
- **为什么这样定**：用户明确选始终自动；零售所惯例也是自动，三层安全已足够、无需人工。
- **影响**：无资金池影响；后台零人工审核负担。
