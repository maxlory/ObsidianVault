## 选项 A：Docker 一键部署（推荐）

Docker 是启动运行系统最快的路径——多阶段 `Dockerfile` 会预构建 React 前端，通过 `uv` 安装所有 Python 依赖，并将所有内容打包进单个镜像，在 8000 端口同时提供 API 和静态前端服务。

```bash
docker pull ghcr.io/kylinmountain/tradingagents-ashare:latest
 
# 2. 创建持久化数据目录
mkdir -p $(pwd)/data
 
# 3. 生成生产环境密钥（用于加密 API 密钥和 JWT）
export TA_APP_SECRET_KEY=$(openssl rand -base64 32)
 
# 4. 启动
docker run -d -p 8000:8000 \
  --name tradingagents \
  -v $(pwd)/data:/app/data \
  -e DATABASE_URL="sqlite:///./data/tradingagents.db" \
  -e TA_APP_SECRET_KEY="${TA_APP_SECRET_KEY}" \
  ghcr.io/kylinmountain/tradingagents-ashare:latest
```

在浏览器中打开 `http://localhost:8000`——你应当能看到登录页面。容器内的启动序列会初始化数据库、预加载 A 股交易日历与股票名称映射，并提升 AnyIO 的线程限制以应对并发的 Agent 工作负载。

**`TA_APP_SECRET_KEY` 对生产环境至关重要。** 它用于加密用户的 LLM API 密钥并签署 JWT 令牌。若未设置，系统将回退到硬编码的默认密钥——这仅适用于本地测试，**切忌在生产环境中不带此配置部署**。一旦设置，若不重新加密已有的密文，该值将无法更改。

## 选项 B：源码安装

如果你需要修改 Agent 逻辑或贡献代码，请选择源码安装。本项目使用 `uv` 进行确定性的 Python 依赖管理，前端则采用 Vite + React + TypeScript。

### 第 1 步 — 克隆并安装后端

```bash
git clone https://github.com/KylinMountain/TradingAgents-AShare.git
cd TradingAgents-AShare
 
# 安装 Python 依赖（需要 uv）
uv sync
```

`uv sync` 命令会读取 `pyproject.toml` 和锁文件，创建一个包含所有后端依赖（LangGraph、LangChain providers、FastAPI、SQLAlchemy、akshare、baostock 等）的可复现虚拟环境。

### 第 2 步 — 构建前端

```bash
cd frontend
npm install
npm run build
cd ..
```

构建输出将存放于 `frontend/dist/`。FastAPI 服务器会自动检测此目录，并将其作为静态文件挂载，同时支持 SPA 回退路由——所有未识别的路径均返回 `index.html`。

### 第 3 步 — 配置并启动

```bash
# 复制环境变量模板并根据需要编辑
cp .env.example .env
 
# 启动后端 API 服务器
uv run python -m uvicorn api.main:app --port 8000
```

访问 `http://localhost:8000` 即可使用应用。前端开发期间也可使用 Vite 开发服务器（端口 5173）——它会将 `/v1`、`/api` 和 `/healthz` 请求代理到 8000 端口的后端。

## 首次分析

应用启动后，从运行到获取首次结果的流程如下：

> **[原图为 mermaid 图；下列为从渲染 SVG 提取的节点/边标签（近拓扑序），非原始 mermaid 源码]**
>

### 1. 注册并登录

前往 `http://localhost:8000` 创建账户。在未配置 SMTP 的本地开发环境中，验证码会直接显示在登录页面，格式为 `开发环境验证码：xxxxxx`——无需邮件服务器。

### 2. 配置 LLM 供应商

进入 **Settings**（⚙️ 图标）并填写以下三个字段：

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| **Provider** | `openai` / `anthropic` / `google` | 路由至正确的 LLM 客户端工厂 |
| **API Key** | `sk-...` | 供应商的身份验证访问密钥 |
| **Model** | `gpt-4o` / `claude-sonnet-4-20250514` | 用于深度分析的特定模型 |

保存后，系统会自动运行一次 **预热** 请求（`POST /v1/config/warmup`）——通过一次轻量级的“hello”调用来验证连通性。你也可以在 Settings 页面手动测试，以检查 LLM 的原始响应。

### 3. 运行首次查询

在主聊天输入框中，输入自然语言查询，例如：

> 调研茅台短线

系统会自动执行以下操作：

1. **解析意图** —— 意图解析器将“茅台”解析为 `600519.SH`，将“短线”解析为 `short` 周期
2. **收集数据** —— 从 akshare/baostock/yfinance 获取技术指标、基本面、新闻、市场情绪、宏观背景及主力资金流向
3. **运行 14 个 Agent** —— 分析师并行辩论，多头/空头研究员在结构化回合中交锋，风险分析师从三个视角进行评估，最终由投资组合经理给出定论

结果是一张结构化决策卡片，包含**方向**（看涨/看跌/中性）、**置信度评分**、**目标价**、**止损价**以及**核心风险**——所有这些均由多 Agent 对抗辩论得出，而非单一 LLM 调用产生。

## 配置快速参考

系统通过环境变量读取配置，并提供了合理的默认值。对于本地开发，多数配置可保持不变——只需关注 `TA_APP_SECRET_KEY` 和你的 LLM 凭证即可。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `TA_APP_SECRET_KEY` | *(硬编码默认值)* | 加密 API 密钥并签署 JWT。**生产环境务必设置。** |
| `DATABASE_URL` | `sqlite:///./tradingagents.db` | 数据库连接字符串 |
| `TA_MAX_WORKERS` | `2` | 最大并发分析任务数 |
| `TA_JOB_TIMEOUT` | `1800`（30 分钟） | 单个分析任务的超时时间（秒） |
| `TA_LLM_PROVIDER` | `openai` | 默认 LLM 供应商 |
| `TA_LLM_DEEP` | `gpt-4o` | 用于分析的深度思考模型 |
| `TA_LLM_QUICK` | `gpt-4o-mini` | 用于路由的快速思考模型 |
| `TA_BASE_URL` | `https://api.openai.com/v1` | LLM API 基础 URL |
| `TA_MAX_DEBATE` | `2` | 最大多空辩论轮数 |
| `TA_MAX_RISK` | `1` | 最大风险辩论轮数 |
| `TA_LANGUAGE` | `zh` | 提示词语言（`zh` / `en` / `auto`） |
| `LOG_LEVEL` | `INFO` | Python 日志级别 |
| `CORS_ALLOW_ORIGINS` | `localhost:5173-5175` | 前端开发用的 CORS 来源 |

**LLM 配置是面向用户的，而非面向实例的。** 每个用户通过 Settings 页面配置各自的供应商和 API 密钥——这些值使用 `TA_APP_SECRET_KEY` 加密并存储在数据库中。诸如 `TA_API_KEY` 和 `TA_LLM_PROVIDER` 等环境变量仅设置*服务器级别*的回退值，一旦用户保存了其个人配置，这些回退值就会被覆盖。

## 可选：调度器进程

对于定时分析任务（例如，在设定时间自动生成日报），可将调度器作为独立进程与 API 服务器一同运行：

```bash
uv run python -m scheduler.main
```

该调度器是一个独立的 `asyncio` 循环，每分钟检查一次到期任务，通过信号量强制控制并发（默认 3 个槽位，可通过 `SCHEDULER_CONCURRENCY` 配置），并使用与 API 相同的 `_run_job` 管道触发分析。它还会在报告生成后处理邮件和企业微信的通知发送。

## 故障排除

| 症状 | 原因 | 解决方案 |
| --- | --- | --- |
| 收不到登录验证码 | 未配置 SMTP | 本地开发时验证码会直接显示在页面上。如需邮件发送，请在 `.env` 中配置 `MAIL_HOST` / `MAIL_USER` / `MAIL_PASS` |
| 日志中出现 `TA_APP_SECRET_KEY` 警告 | 未设置密钥 | 生成一个密钥：`openssl rand -base64 32`，并将其设置为环境变量 |
| LLM 预热失败 | API 密钥或基础 URL 无效 | 在 Settings 中验证凭证 → 点击手动测试查看原始响应 |
| 分析挂起 / 超时 | 并发任务过多或 LLM 响应缓慢 | 增加 `TA_MAX_WORKERS` 或 `TA_JOB_TIMEOUT` |
| SQLAlchemy 超时错误 | 数据库锁争用 | 确保启用了 WAL 模式（当数据目录可写时会自动启用） |
