提供者注册表模式（Provider Registry Pattern）是 TradingAgents-AShare 的数据访问骨干——一个**契约优先、配置驱动的路由层**，它将每个 Agent 和服务与其所使用的具体市场数据源解耦。系统不再代码库中硬编码对 YFinance、Alpha Vantage、AkShare 或 BaoStock 的 API 调用，而是让所有数据请求流经单一的 `route_to_vendor()` 调度器，该调度器在运行时解析出正确的提供者，并在提供者失败或缺少实现时自动进行降级链式回退。正是这种设计，使得系统能够将 A 股和全球市场数据视为统一的接口，仅通过配置即可替换整个数据后端。

## 架构概述

该模式遵循经典的**策略模式 + 注册表模式 + 责任链模式**的组合。抽象契约定义在 `BaseMarketDataProvider` 中；具体实现将自身注册到内存中的 `DataProviderRegistry`；`interface.py` 路由层从配置中读取供应商偏好，并遍历回退链，直到某个提供者成功返回。下图展示了完整的请求生命周期：

> **[原图为 mermaid 图；下列为从渲染 SVG 提取的节点/边标签（近拓扑序），非原始 mermaid 源码]**
>
> DataProviderRegistry → interface.py — 路由层 → Consumers → 分析师 Agent → 数据收集器 → API 服务 → route_to_vendor() → get_vendor / config[] → _resolve_vendor_chain() → cn_akshareCnAkshareProvider → cn_baostockCnBaoStockProvider → yfinanceYFinanceProvider → alpha_vantageAlphaVantageProvider → cn_stubCnStubProvider

每次调用都通过 `route_to_vendor` 进入，该函数确定配置好的供应商链，然后按优先级顺序遍历提供者——跳过未实现该方法的提供者，并在出现任何异常时向下顺延。这意味着部分提供者（例如仅实现了价格和指标的 `cn_baostock`）可以与完整提供者共存于同一链中，而不会中断调度循环。

## 抽象契约 — BaseMarketDataProvider

`BaseMarketDataProvider` 是一个抽象基类（ABC），它声明了每个提供者必须满足的**方法接口**。它定义了 10 个核心数据方法，每个方法均返回 `str`（通常是 CSV 或 markdown 格式的文本），从而确保所有提供者以统一格式产出 Agent 提示词可解析的输出：

| 方法 | 类别 | 描述 |
| --- | --- | --- |
| `get_stock_data` | core_stock_apis | 历史 OHLCV 价格数据 |
| `get_indicators` | technical_indicators | 技术分析指标（SMA、MACD、RSI 等） |
| `get_fundamentals` | fundamental_data | 公司基本面概览 |
| `get_balance_sheet` | fundamental_data | 资产负债表财务报告 |
| `get_cashflow` | fundamental_data | 现金流量表 |
| `get_income_statement` | fundamental_data | 利润表 |
| `get_news` | news_data | 个股新闻资讯 |
| `get_global_news` | news_data | 全球市场新闻动态 |
| `get_insider_transactions` | news_data | 内部交易数据 |
| `get_realtime_quotes` | realtime_data | 实时行情快照（非抽象方法，抛出 `NotImplementedError`） |

关键的设计选择在于，`get_realtime_quotes` **未**使用 `@abstractmethod` 装饰器——它是一个默认抛出异常的方法。不支持实时数据的提供者只需保持其未被覆写，路由器的 `getattr(provider, method, None)` 检查结合 `NotImplementedError` 捕获机制将确保平滑降级。此模式允许契约演进：可以添加新方法而不破坏现有提供者。

添加新数据方法时，请将其作为抛出 `NotImplementedError` 的非抽象方法添加到 `BaseMarketDataProvider` 中。然后在 `interface.py` 的 `TOOLS_CATEGORIES` 字典中注册该方法名——路由层使用此映射来确定要读取的供应商配置键。跳过类别注册将导致 `route_to_vendor` 在调度时抛出 `ValueError`。

## 提供者实现

代码库内置了五个提供者，分别针对不同的市场或数据深度：

### YFinanceProvider — 全球市场默认

非中国股票最完整的提供者。它封装了遗留的 `y_finance.py` 和 `yfinance_news.py` 模块，将每个方法调用委托给底层函数。一个值得注意的细节是其 `_normalize_symbol` 方法：yfinance 对上海股票使用 `.SS` 后缀，而系统其余部分使用 `.SH`，因此该提供者在边界处透明地转换股票代码。

### AlphaVantageProvider — 高级全球备选

封装了 Alpha Vantage API 家族（`alpha_vantage_stock.py`、`alpha_vantage_indicator.py` 等）。实现了完整的方法接口。其价值在于为美国上市公司提供比 yfinance 更高质量的基本面数据，尽管它受限于速率限制，会触发 `AlphaVantageRateLimitError`——路由器会专门捕获此异常以触发降级回退。

### CnAkshareProvider — A 股首选

系统中最复杂的提供者，由 AkShare 库提供支持。除了标准方法接口外，它还实现了五个**A 股特有**的方法（`get_board_fund_flow`、`get_individual_fund_flow`、`get_lhb_detail`、`get_zt_pool`、`get_hot_stocks_xq`），这些方法用于暴露中国市场情绪数据——板块资金流向、龙虎榜、涨停池以及雪球热门股。在内部，它具有单个方法内的多源回退机制：例如，`get_stock_data` 依次尝试东方财富 → 新浪 → 腾讯，而 `_fetch_realtime_row` 在带有 TTL 缓存的情况下从新浪回退到东方财富。它还包含一个复杂的并发控制系统（`_AkshareLock`），该系统将 AkShare 的总并发调用数限制为 5，为前端请求保留至少 2 个槽位，并在 120 秒后自动回收“僵尸线程”的许可。

### CnBaoStockProvider — A 股轻量级备用

由 BaoStock 支持的更简单的 A 股提供者。它仅实现 `get_stock_data` 和 `get_indicators`——其他所有方法均抛出 `NotImplementedError`，路由器捕获此异常以顺延至下一个提供者。这使其成为链中极佳的**回退选项**：当 AkShare 的速率限制或反爬虫措施阻止请求时，BaoStock 通常能提供基础价格数据。

### CnStubProvider — 哨兵占位符

具有 `is_placeholder = True` 属性的特殊提供者。其所有方法均抛出带有指引信息（将用户导向具体提供者）的 `NotImplementedError`。路由器的 `_resolve_vendor_chain` 在自动追加回退供应商时会显式跳过占位符提供者，防止它们污染链路，同时在用户需要时仍允许显式配置 `"cn_stub"`。

## 注册表与引导

`DataProviderRegistry` 是一个以提供者名称为键的最小化内存字典。它暴露三个操作：

| 方法 | 用途 |
| --- | --- |
| `register(provider)` | 添加一个 `BaseMarketDataProvider` 实例，以 `name` 属性为键 |
| `get(provider_name)` | 按名称检索提供者，未找到则返回 `None` |
| `list_names()` | 按插入顺序返回所有已注册提供者的名称 |

工厂函数 `build_default_registry()` 构建并使用全部五个提供者填充注册表。此函数在 `interface.py` 的模块导入时调用一次，创建一个进程级单例注册表，服务于所有后续路由操作：

```python
_registry = build_default_registry()
VENDOR_LIST = _registry.list_names()
```

要添加自定义提供者（例如基于 Tushare 的实现），请创建一个继承 `BaseMarketDataProvider` 的新类，然后在 `build_default_registry()` 中注册它。路由层将自动发现它——无需其他连接配置。如果你的提供者仅覆盖 A 股数据，请对全球方法抛出 `NotImplementedError`，以便路由器平滑降级回退至 yfinance 或 alpha_vantage。

## 路由引擎 — `route_to_vendor` 的工作原理

路由引擎是该模式的核心。当任何消费者调用 `route_to_vendor("get_stock_data", "600519.SH", "2025-01-01", "2025-01-31")` 时，将经历以下流程：

**步骤 1 — 类别解析。** 在 `TOOLS_CATEGORIES` 中查找方法名以确定其类别（例如，`get_stock_data` → `core_stock_apis`）。此类别是读取供应商配置的键。

**步骤 2 — 供应商配置查找。** 路由层从活动配置中读取 `tool_vendors`（方法级覆盖）和 `data_vendors`（类别级默认）。方法级配置优先于类别级，从而实现细粒度路由，例如“基本面数据使用 alpha_vantage，其余均使用 yfinance”。

**步骤 3 — 回退链构建。** `_resolve_vendor_chain` 按逗号分割配置的供应商字符串（例如，`"cn_akshare,cn_baostock,yfinance"` 成为优先前缀），然后追加所有不在列表中且非占位符的剩余已注册提供者。这确保了即使用户只配置了 `"cn_akshare"`，系统仍会尝试将 `cn_baostock`、`yfinance` 和 `alpha_vantage` 作为自动回退。

**步骤 4 — 迭代调度。** 对于链中的每个供应商，路由器检查： 是否已注册？ 是否实现了该方法？ 调用是否成功？ 如果任何检查失败，它将记录一条追踪日志并移至下一个供应商。如果所有供应商均失败，则抛出包含完整链路和最后异常详情的 `RuntimeError`。

> **[原图为 mermaid 图；下列为从渲染 SVG 提取的节点/边标签（近拓扑序），非原始 mermaid 源码]**
>
> 否 → 是 → 成功 → 异常 → 全部耗尽 → route_to_vendor(method, *args) → get_category_for_method(method) → get_vendor(category, method) → _resolve_vendor_chain(method, vendor_config) → 对于链中的每个供应商 → 提供者已注册？ → 跳过 → 下一个 → 方法已实现？ → impl_func(*args, **kwargs) → 返回结果 ✓ → 记录日志 → 下一个供应商 → RuntimeError: 无可用供应商

## 配置驱动的供应商选择

供应商链完全由 `DEFAULT_CONFIG` 字典（或通过 `set_config` 进行的运行时覆盖）驱动。相关的配置键如下：

| 配置键 | 类型 | 示例 | 描述 |
| --- | --- | --- | --- |
| `data_vendors` | `dict[str, str]` | `{"core_stock_apis": "cn_akshare,cn_baostock,yfinance"}` | 类别 → 逗号分隔的供应商优先级列表 |
| `tool_vendors` | `dict[str, str]` | `{"get_news": "cn_akshare"}` | 方法级覆盖（优先于类别） |
| `provider_trace` | `bool` | `True` | 启用显示路由决策的 `[provider-trace]` 日志行 |

默认的 A 股配置优先考虑中国数据源：

```python
"data_vendors": {
    "core_stock_apis": "cn_akshare,cn_baostock,yfinance",
    "technical_indicators": "cn_akshare,cn_baostock,yfinance",
    "fundamental_data": "cn_akshare,cn_baostock,yfinance",
    "news_data": "cn_akshare,cn_baostock,yfinance",
    "realtime_data": "cn_akshare",
}
```

这意味着对于 A 股，系统首先尝试 AkShare（数据最丰富），然后是 BaoStock（价格数据的可靠备份），最后是 yfinance（作为兜底的全局覆盖）。对于实时数据，仅配置了 AkShare，因为没有其他提供者为中国股票实现 `get_realtime_quotes`。逗号分隔的语法支持无需更改代码即可快速重新配置——通过环境变量设置 `TA_DATA_VENDORS_CORE_STOCK_APIS=yfinance` 将翻转该类别的整个优先级。

## 追踪日志 — 路由边界的可观测性

路由层包含一个内置的追踪工具，用于记录每个调度决策。当 `provider_trace` 启用（默认）时，每次 `route_to_vendor` 调用都会发出结构化的日志行，例如：

```

[provider-trace] method=get_stock_data symbol='600519.SH' vendor=cn_akshare status=hit
```

或在降级回退时：

```
[provider-trace] method=get_fundamentals symbol='600519.SH' vendor=cn_akshare status=fallback reason=NotImplementedError: cn_akshare is temporarily unavailable
[provider-trace] method=get_fundamentals symbol='600519.SH' vendor=cn_baostock status=skip reason=not-implemented
[provider-trace] method=get_fundamentals symbol='600519.SH' vendor=yfinance status=hit
```

追踪输出包括方法名称、前几个参数（股票代码、日期）的摘要、配置的供应商字符串、完全解析的链路，以及每次提供者尝试的结果（`hit`、`skip`、`fallback`）。这对于调试生产环境中的数据可用性问题极具价值——你可以准确看到哪个提供者服务了请求以及为何跳过其他提供者。

## CnAkshareProvider 中的并发控制

AkShare 封装了针对中国金融网站（东方财富、新浪、雪球）的网页抓取，这些网站对反机器人速率限制非常严格。为了防止系统在并发负载下自我 DDoS（尤其是在计划任务和前端请求同时到达时），`CnAkshareProvider` 部署了一个自定义的 `_AkshareLock`，它实现了**带僵尸回收的优先级信号量**：

| 参数 | 值 | 用途 |
| --- | --- | --- |
| `total` | 5 | 所有请求类型的最大并发 AkShare 调用数 |
| `scheduled_max` | 3 | 计划/后台任务可占用的最大槽位数 |
| `ACQUIRE_TIMEOUT` | 60s | 放弃获取槽位前的最长等待时间 |
| `STALE_TIMEOUT` | 120s | 超过此持续时间后，持有的许可将被视为僵尸并自动回收 |

该锁使用 `contextvars.ContextVar` 将 `is_scheduled_task` 标志从 asyncio 上下文传播到工作线程，允许 `_AkshareLock.__enter__` 决定是否在获取总信号量之外还需获取计划信号量。如果线程持有许可超过 120 秒（例如，因为父 `asyncio.to_thread` 超时但底层线程继续运行），`_reclaim_stale` 会检测到它，从 `_holders` 中移除该条目，并释放信号量——从而防止僵尸线程导致的锁耗尽。

## 如何扩展 — 添加新提供者

向注册表添加新数据源需要三个步骤，且无需更改路由引擎：

1. **创建提供者类** — 继承 `BaseMarketDataProvider`，实现 `name` 属性，并覆写你的数据源支持的任何方法。未实现的方法将抛出 `NotImplementedError`（继承自基类），导致路由器跳至下一个提供者。
2. **在默认注册表中注册** — 在 `registry.py` 的 `build_default_registry()` 中添加 `registry.register(YourNewProvider())`。
3. **可选地添加到供应商配置** — 更新 `default_config.py` 中的 `data_vendors` 或 `tool_vendors` 条目（或在运行时覆盖），以在相关类别的优先级链中包含你的提供者名称。

对于不在现有 `TOOLS_CATEGORIES` 映射中的方法，你还需要在 `interface.py` 中添加类别条目——否则 `get_category_for_method` 将抛出 `ValueError`。
