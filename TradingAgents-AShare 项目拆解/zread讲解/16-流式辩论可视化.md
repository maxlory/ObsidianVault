## 辩论的 SSE 事件分类

后端为辩论流式传输发射两种专用的 SSE 事件类型。每个事件都携带结构化元数据，前端利用这些元数据将 token 路由至正确辩论类型中对应的 Agent 和回合。

| SSE 事件类型 | 用途 | 关键字段 | 前端处理器 |
| --- | --- | --- | --- |
| `agent.debate` | 完整辩论消息（Agent 回合结束时） | `debate`, `agent`, `round`, `content`, `isVerdict`, `horizon` | `addDebateMessage()` |
| `agent.debate.token` | 流式 token 片段（生成期间） | `debate`, `agent`, `round`, `token`, `horizon` | `appendDebateToken()` |

这种**双事件模式**是有意为之的：`agent.debate.token` 提供了实时的打字机体验，而 `agent.debate` 则传递最终的权威内容，覆盖之前累积的所有流式生成残留。这确保了即使在网络传输中 token 顺序被打乱，完成后的消息也始终是正确的。

## Zustand Store：辩论状态架构

`analysisStore` 管理着两个关键的辩论状态：`debateMessages`（一个以辩论类型为键的 `Record<string, DebateMessage[]>`）和 `debateScrollTick`（一个单调递增的计数器，用于触发自动滚动）。本节将探讨使流式辩论保持稳定的更新插入机制。

### 更新插入模式

当 token 通过 `appendDebateToken` 到达时，store 会使用 `(agent, round)` 组合键执行**查找或创建**操作。如果该 Agent 在该回合的消息已存在，则将 token 追加到其 `content` 字段。如果不存在，则使用该 token 作为初始内容创建一个新的 `DebateMessage` 对象。这是使时间轴能够随着 Agent 发言而有机增长的核心机制：

```typescript
// Simplified from analysisStore.ts — appendDebateToken
appendDebateToken: (debate, agent, round, token, horizon) => set((state) => {
    const existing = state.debateMessages[debate] || []
    const idx = existing.findIndex(m => m.agent === agent && m.round === round)
    if (idx >= 0) {
        // Token append to existing message — stable DOM node
        const updated = existing.map((m, i) =>
            i === idx ? { ...m, content: m.content + token } : m
        )
        return { debateMessages: { ...state.debateMessages, [debate]: updated }, debateScrollTick: tick }
    }
    // New message — creates fresh DebateMessage entry
    return {
        debateMessages: {
            ...state.debateMessages,
            [debate]: [...existing, { debate, agent, round, content: token, isVerdict, horizon }],
        },
        debateScrollTick: tick,
    }
})
```

`debateScrollTick` 计数器是实现平滑自动滚动的秘诀。与监听 `messages.length`（仅在产生新消息时变化）不同，该计数器在**每个 token 到达时**都会递增，为 `DebateDrawer` 的 `useEffect` 提供高频信号以向下滚动容器——同时通过 `userScrolledUp` ref 尊重用户的滚动位置。

`addDebateMessage` 动作遵循类似的更新插入模式，但它会替换整个消息内容而非追加，使其在后端发射完整的 `agent.debate` 事件时成为权威的覆盖操作。

`AgentCollaboration` 组件是进入辩论抽屉的**主要导航网关**。它基于 `@xyflow/react`（React Flow）构建，将完整的 15 Agent 工作流渲染为一个交互式节点图，其中：

## 自动滚动：用户体验契约

`DebateDrawer` 中的自动滚动行为实现了一种**尊重用户的滚动**契约：视图会自动追踪时间轴底部的新内容，但当用户手动向上滚动以阅读先前的论点时，**立即停止**自动滚动。其阈值为 80 像素——如果 `scrollHeight - scrollTop - clientHeight > 80`，`userScrolledUp` ref 就会被设为 `true`，随后的 `scrollTick` 变化将被忽略。

此机制确保了在 token 高频发射的实时辩论中，用户可以自由回看先前回合的论点，而无需与自动滚动“搏斗”。基于 ref（而非基于 state）的方式避免了对每个滚动事件的重新渲染，使得 UI 即使在高频 token 流期间也能保持响应迅速。

## 数据类型契约：DebateMessage

`DebateMessage` 类型是后端 SSE 事件与前端渲染逻辑之间的基础契约。其结构决定了消息如何分组、着色和显示：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `debate` | `'research' \| 'risk'` | 将消息路由至正确的抽屉 |

组合键 `(agent, round)` 既用于 store 中的更新插入操作，也用作时间轴中的 React `key` 属性，从而确保流式更新期间的 DOM 稳定性。
