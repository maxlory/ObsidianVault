## 统一的 Agent 工厂模式

每位分析师都遵循相同的结构契约——一个 `create_*_analyst(llm, data_collector=None)` 工厂函数，该函数返回一个与 LangGraph 的 `(state) → dict` 签名匹配的异步节点函数。这种一致性使得扇出/扇入模式即插即用：添加新维度只需实现相同的工厂函数并在 `GraphSetup` 中注册即可。

```python
# 所有7名分析师共享的简化规范结构
def create_xxx_analyst(llm, data_collector=None):
    async def xxx_analyst_node(state):
        # 1. 从状态中读取上下文
        ticker = state["company_of_interest"]
        current_date = state["trade_date"]
        horizon = "short" | "medium"  # 每位分析师固定
 
        # 2. 获取数据（缓存池或直接工具调用）
        pool = data_collector.get(ticker, current_date) if data_collector else None
        # ... 特定领域的数据组装 ...
 
        # 3. 构建消息（系统提示词 + 视野上下文 + 数据）
        messages = [SystemMessage(...), HumanMessage(...)]
 
        # 4. 流式传输 LLM 输出，向 tracker 发送 token
        full_content = ""
        async for chunk in llm.astream(messages):
            full_content += chunk.content
            if tracker: tracker._emit_token(...)
 
        # 5. 提取判定，返回状态更新
        verdict, confidence = extract_verdict(full_content)
        return {
            "xxx_report": full_content,
            "analyst_traces": [{ agent, horizon, verdict, confidence, ... }],
        }
    return xxx_analyst_node
```

`extract_verdict` 函数会解析一个隐藏的 HTML 注释块（`<!-- VERDICT: {"direction": "...", "reason": "..."} -->`），每位分析师都被指示在其报告末尾附加该块。这种机器可读的判定正是研究经理（Research Manager）后来用来构建多维信号全景视图的依据。

## 视野分配与意图感知上下文

每位分析师都被硬编码为反映其领域自然决策周期的特定时间视野。**短期**分析师（市场、新闻、社交媒体、聪明钱、量价）在 14 天的数据窗口上运作，而**中期**分析师（基本面、宏观）则使用 90 天的数据窗口。这种分离是刻意为之的：它防止短期噪音污染基本面判断，并确保技术信号不被滞后指标稀释。

除了固定视野外，每位分析师还会接收一个由 `build_horizon_context` 构建的**视野上下文块**，该上下文块注入了从原始自然语言查询中解析出的用户的 `focus_areas` 和 `specific_questions`。这意味着，如果用户提问“比亚迪短期主力资金在做什么？”，聪明钱分析师将看到明确的指令，要求其分析侧重于短期资金流行为。

### 7. 量价分析师 — 基于 Wyckoff 的 VPA 解读

这是理论基础最扎实的分析师，其系统提示词是 Anna Coulling 的《量价分析》框架的浓缩版，该框架建立在 Wyckoff 三大定律（供求定律、因果定律、努力与结果定律）之上。与读取单个指标的市场分析师不同，VPA 分析师从 `DataCollector` 接收**预计算的 VPA 指标**——一个包含每日 K 线类型、成交量比率、价差、收盘位置、影线比率和量价和谐分类的丰富表格。关键模式检测（卖出高潮、买入高潮、射击之星、锤子线、量价背离）在 `_compute_vpa_indicators` 中通过计算完成，因此 LLM 只需解读结果，无需进行算术运算。该分析师识别当前的 Wyckoff 市场阶段（吸筹、拉升、派发、下跌），并对每个信号的可靠性进行评级。

`DataCollector._compute_vpa_indicators` 中的 VPA 预计算是系统中最复杂的数据预处理步骤——它将原始 OHLCV 转换为带有派生列（成交量比率、K线价差、收盘位置、量价和谐）的人类可读 Markdown 表格，并附加自动模式识别结果。这确保了 LLM 接收到确定性、可复现的信号，而不是试图对原始价格数据进行不可靠的数值推理。

## 判定提取与追踪传播

每份分析师报告都以一个隐藏的机器可读块结尾：`<!-- VERDICT: {"direction": "看多", "reason": "..."} -->`。`extract_verdict` 函数解析此块并返回一个 `(direction, confidence)` 元组。五个允许的方向是：**看多**（bullish）、**偏多**（leaning bullish）、**中性**（neutral）、**偏空**（leaning bearish）、**看空**（bearish）。如果找到有效的判定，置信度默认为“中”，否则为“低”。

每位分析师都会向状态中的 `analyst_traces` 列表追加一个 `TraceItem`，该列表使用 `operator.add` 归约器——这意味着所有七位分析师的追踪记录会累加而不会相互覆盖。研究经理随后遍历这些追踪记录，以构建其全景判定概览，并根据视野相关性和市场状态对每个维度进行加权。

```python
# 每位分析师写入的追踪结构
{
    "agent": "market_analyst",      # 分析师标识符
    "horizon": "short",              # 固定时间视野
    "data_window": "14天",           # 实际数据覆盖范围
    "key_finding": "市场技术面结论：偏多",
    "verdict": "偏多",               # 从 VERDICT 块解析
    "confidence": "中",              # 置信度
}
```

## Token 级流式传输

所有七位分析师都使用 `llm.astream(messages)` 共享相同的流式传输模式。随着每个 token 块到达，它会被追加到 `full_content` 中，并同时发送到 `current_tracker_var` ContextVar，该变量持有由 API 层在图执行前设置的 `AgentProgressTracker` 实例。这使得前端能够逐字符实时渲染分析师报告，而无需等待全部生成完成。

```python
tracker = current_tracker_var.get()
full_content = ""
async for chunk in llm.astream(messages):
    content = chunk.content if hasattr(chunk, "content") else str(chunk)
    full_content += content
    if tracker:
        tracker._emit_token("Market Analyst", "market_report", content)
```

`current_tracker_var` 是一个 `contextvars.ContextVar` 而非状态字段，因为 tracker 不可序列化，且不应持久化在 LangGraph 的检查点系统中。

## 可配置名单与选择性激活

`GraphSetup.setup_graph` 方法接受一个 `selected_analysts` 参数，该参数控制实例化哪些分析师并将其连接到图中。默认名单为 `["market", "social", "news", "fundamentals", "macro", "smart_money"]`——七选六。量价分析师为可选项，通过将 `"volume_price"` 添加到列表中来激活。空列表将引发 `ValueError`，确保流水线始终至少有一个证据来源。

添加新的分析师维度时，你必须：(1) 在 `tradingagents/agents/analysts/` 中创建分析师模块，(2) 在 `setup.py` 的 `_load_agent_factories()` 中注册工厂，(3) 将报告键和追踪逻辑添加到 `AgentState`，以及 (4) 将相应的 `should_continue_*` 方法添加到 `ConditionalLogic`。缺少这四个注册点中的任何一个都会导致图编译时出现运行时错误。

来源：[setup.py](https://github.com/KylinMountain/TradingAgents-AShare/blob/main/tradingagents/graph/setup.py#L112-L148), [setup.py](https://github.com/KylinMountain/TradingAgents-AShare/blob/main/tradingagents/graph/setup.py#L19-L50)

## 从证据到辩论

这七份分析师报告直接流入多空辩论阶段。看多研究员接收所有报告作为上下文变量，并使用它们构建看多论点；看空研究员则针对看空情况执行相同操作。然后，研究经理综合双方观点，参考 `analyst_traces` 获取每个维度判定的结构化概览，并根据视野和市场状态对其进行加权。正是这种多维证据基础，使得辩论具有实质性而非推测性——每一个主张都必须追溯到特定分析师基于数据的发现。

要了解这些报告如何在结构化辩论中被用作武器，请继续阅读[声明驱动的多空辩论 ](https://zread.ai/KylinMountain/TradingAgents-AShare/8-claim-driven-bull-bear-debate)。关于使双路径获取模式成为可能的数据基础设施，请参阅[数据收集器与缓存 ](https://zread.ai/KylinMountain/TradingAgents-AShare/10-data-collector-and-caching)。
