## 🔴 冲突 1：分析师的「工具调用循环」根本不存在

**zread 说**（`04-LangGraph 状态机#L51`）：
> 每个选定的分析师在图中生成**三个节点**：分析师节点本身、一个配套的 `ToolNode`，以及一个"完成"哨兵节点。分析师节点和工具节点构成一个微型循环（调用 → 工具调用 → 调用 → 完成）

**zread 还说**（`05-条件路由与辩论循环#L38`）：
> 工具循环是无界的——只要 LLM 持续发出 `tool_calls`，分析师就可以无限期地调用工具。**在实践中，LLM 的行为通常在 2-3 次迭代后自然收敛。**

**源码实测**：
- 全仓库 `grep bind_tools` → **0 命中**。LLM 从未绑定任何工具
- 15 个 agent 全部走 `llm.astream(messages)`，数据是 `DataCollector` 预先抓好、直接拼进 `HumanMessage` 的（`tradingagents/agents/analysts/market_analyst.py#L58-63`）
- 初始 state 的 `messages` 是 `[("human", ...)]`（`tradingagents/graph/propagation.py#L51`），human 消息没有 `tool_calls` 属性
- → `should_continue_*` 恒返回 `"done"`，**`ToolNode` 执行 0 次**

**这条错误的实际代价**：
按 zread 的说法算成本，7 个分析师 × 2-3 次迭代 = 14~21 次 LLM 调用；实际是 **7 次**。整轮分析实际约 18 次调用（最坏 21 次），不是 zread 描述的循环架构下的不可预测次数。**"2-3 次迭代后自然收敛"这句是从代码结构推测出来的，不是观测到的行为。**

## 🔴 冲突 2：把「架构残留」美化成了「深思熟虑的前瞻设计」

**zread 说**（`04-LangGraph 状态机#L201`）：
> 每种分析师类型都有其专属的 `should_continue_{type}` 函数，而不是共享一个通用函数。**这是一个深思熟虑的设计选择**——它允许未来每位分析师的工具调用终止逻辑产生差异，而无需重构条件边映射。目前所有七个实现完全相同，但**这种架构预见到了未来的专门化**。

**源码实测**：
这 7 个函数（`tradingagents/graph/conditional_logic.py#L15-69`）逐字相同且恒返回 `"done"`，是从上游 `TauricResearch/TradingAgents` 的 ReAct 架构改造成"预抓取 + 单轮推理"时**没删干净的骨架残留**。

判据：如果是为未来专门化预留，`bind_tools` 至少该存在于某处；实际是 0 处。**没有工具绑定的"工具调用终止逻辑"不构成设计，只是遗留。**

**对二次开发的影响**：这 7 个函数 + 7 个 `ToolNode` 是"不写会崩（`setup.py#L213` 用 getattr 反射取、`#L112` 用字典索引取）、写了不执行"的仪式代码。加新分析师时会被绕晕。建议第一个 commit 就清掉。

## 🔴 冲突 3：BM25 分词「在中英文上产生一致结果」——实测是中文完全失效

**zread 说**（`18-记忆与反思系统#L38`）：
> 分词器使用简单有效的正则表达式 `r'\b\w+\b'` 并转换为小写——在单词边界处拆分并去除标点符号。这一选择意义重大：它避免了对特定提供商分词器的依赖，消除了对外部 NLP 库的依赖，**并在中英文文本上产生一致的结果**。

**源码实测**（我实跑了 `tradingagents/agents/utils/memory.py#L33` 的分词逻辑）：

```
文档「高通胀伴随利率上升，消费者支出下滑」→ ['高通胀伴随利率上升', '消费者支出下滑']
查询「通胀高企且利率走高，消费下滑」    → ['通胀高企且利率走高', '消费下滑']
交集 = set()   ← BM25 得分 0

英文对照 'High inflation with rising interest rates'
        → ['high','inflation','with','rising','interest','rates']  ✅ 正常
```

`\w+` 对中文匹配的是**连续中文串整体**，不做切分。两句语义高度相似的中文，词交集为空 → BM25 打分 0 → **中文检索完全失效**。

而这个项目的 prompt 默认语言就是中文（`tradingagents/default_config.py#L27` `prompt_language` 默认 `"zh"`），存进 memory 的反思文本也是中文。**"一致的结果"这个结论是错的，且方向反了——它在中文上不是"一致"，是"不工作"。**

修法：换 jieba 分词，或按字做 bigram。

## 🟡 冲突 4：描述的是「代码提供的能力」，不是「实际运行的行为」

**zread 说**（`18-记忆与反思系统#L8`）：
> 记忆与反思系统赋予了 TradingAgents 经验学习能力——这是一种闭环机制…**Agent 能够积累随时间复利的机构知识**，从而减少重复犯错

zread 确实也提到了内存限制（`#L222`）：
> 当前实现仅将记忆存储在内存中——它们在单个 `TradingAgentsGraph` 实例内的多次 `propagate()` / `reflect_and_remember()` 循环中得以存活，但在进程重启时会丢失。

**这段对了一半，但漏了决定性的一环**：

- `reflect_and_remember` 只在 `tradingagents/graph/trading_graph.py#L468` **定义**，在 `api/`、`scheduler/` 中**零调用**（实测 grep，排除 tests）
- `api/main.py#L1784` 每个分析 job 都 `TradingAgentsGraph(...)` **新建实例**，5 个 memory 随之新建为空
- → 两者叠加：`get_memories()` 永远返回 `[]`，所有 agent prompt 里的 `past_memory_str` 恒为空字符串

**所以"随时间复利的机构知识"在当前 Web 部署下一次也没发生过。** zread 描述的是 `reflect_and_remember` 这个方法若被调用会产生的效果——但没人调用它。这是 AI 读代码的典型盲区：**它能看懂函数写了什么，看不出这个函数没有调用方。**
