## 🔑 五个最值得知道的发现

### 1. 你那条 TDD 批注有答案了

`tdd`（37 行 + `tests.md` 77 行 + `mocking.md`）**比 ECC 的 `tdd-workflow`（584 行）好得多**：

| | ECC | mattpocock |
|---|---|---|
| 核心要求 | **80%+ 覆盖率** | **先和用户约定测哪些 seam**——"No test is written at an unconfirmed seam" |
| 反模式 | 无专门章节 | **三个反模式各带识别信号**（implementation-coupled / tautological / horizontal slicing） |
| refactor | 在红绿循环内 | **移出循环，归入 review 阶段** |

覆盖率是个容易被 Goodhart 化的指标（为了数字写无意义测试）；"先约定 seam"承认"你测不完所有东西"，把测试投入引导到关键路径。**建议用它替代 ECC 的 tdd-workflow。**

### 2. 它用「把该人决定的事交给人」解决了你上一轮问的漏调用问题

**9 / 17 个 skill 是 user-invoked**（`disable-model-invocation: true` + Codex 侧 `allow_implicit_invocation: false`），**只有你打字才能触发**。剩下 8 个是 model-invoked 的参考工具。

对比：**ECC 43 个 skill 无一使用这个字段，全部靠模型自主判断，所以必然有漏。**

逻辑很清楚——**需要人做判断的流程节点**（该不该 grilling、要不要拆 ticket）不给模型自主决定的机会；**需要在干活过程中随时被拉进来的参考**（怎么写测试、怎么诊断 bug）才交给模型。

### 3. 社区真实度是 ECC 的 6 倍（同一套方法测的）

| | mattpocock | ECC |
|---|---|---|
| 评论总数 | 1,080 | 8,003 |
| bot 占比 | **5.6%**（只有 changeset-bot） | **68.7%**（3 个 AI 审查 bot + 作者自己的 bot） |
| **真实第三方评论** | **783（72.5%）** | **979（12.2%）** |

star 数同量级（200k vs 237k），但 ECC 要用 8 倍的评论总量才产生接近的第三方参与量。

### 4. SKILL.md 的形态完全相反——这才是 progressive disclosure 的正确实现

| | mattpocock/engineering | ECC/workflow-quality |
|---|---|---|
| 中位行数 | **76** | 189 |
| 最长 | **135** | **889** |
| 纯单文件 | **0%** | **84%** |
| 常驻成本 | **800 token/轮** | 2,715（默认 module）/ 18,919（全装） |

mattpocock 的 SKILL.md 只负责"这次要不要用我"的触发判断，细节全在 `DEEPENING.md` / `tests.md` 这类附加文件里，模型确认相关后才读。**ECC 把 889 行塞进一个 SKILL.md，等于放弃了分层加载的收益。**

### 5. 三条可以立刻用的硬规则

1. **「拿到一条会因为这个 bug 变红的命令之前，拒绝做任何理论推测」**（`diagnosing-bugs` Phase 1 的完成判据）——精确对治 AI 上来就猜原因、改一堆东西、然后说"应该好了"。你的「2 轮收手」是止损，这条是防损
2. **「一个 adapter 只是假想的 seam，两个才是真的」**（`DEEPENING.md`）——单条判据判断任何抽象是否过度设计
3. **「`/handoff` forks，`/compact` continues」**——前者开新会话引用文件，后者留在同一会话让早期轮次被摘要。**别在 phase 中途 compact**。而且有个量化边界：**smart zone ≈ 120k token**，接近就换线程，不要在退化状态下硬撑

## 一个给你自己 skill 库的结构性建议

**引入他的 bucket 制度。** 你现在 `~/.claude/skills/` 是 79 个平铺目录，没有"日常主力 / 备查 / 进行中 / 已替代"的分层——后果和 ECC 一样：旧的、实验性的、已被替代的 skill 混在一起吃 catalog token 且互相竞争触发。

最小改造：加一份 `SKILLS-INDEX.md`（等价于他的 bucket README），标出分层。配合从 ECC 取的 `skill-stocktake` 跑一次审计拿分层依据。
