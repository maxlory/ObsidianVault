Step 1：定义 State — "这个 agent 需要记住/传递哪些信息？"（AgentState就是蓝图，state就是状态框，经过各种节点变为不同的状态）

class AgentState(TypedDict):
    messages: list          # 对话历史
    current_task: str       # 当前在做什么
    tool_results: list      # 工具返回的结果
    final_answer: str       # 最终输出

Step 2：定义 Nodes — "每一步具体做什么？"

def call_llm(state):
    """让 LLM 思考下一步行动"""
    response = model.invoke(state["messages"])
    return {"messages": state["messages"] + [response]}

def use_tool(state):
    """执行 LLM 决定调用的工具"""
    result = execute_tool(last_message)
    return {"tool_results": state["tool_results"] + [result]}

def generate_answer(state):
    """汇总信息，生成最终回答"""
    answer = model.invoke("根据以下信息回答..." + str(state["tool_results"]))
    return {"final_answer": answer}

▎ 每个函数就是审批链上的一个部门——接收表格，做自己的事，把结果写回表格。

Step 3：定义 Edges — "步骤之间怎么跳转？"（条件边）

def should_use_tool(state):
    """条件判断：LLM 是想用工具，还是直接回答？"""
    last_msg = state["messages"][-1]
    if last_msg.tool_calls:       # LLM 说"我要用工具"
        return "use_tool"
    else:                          # LLM 说"我可以直接回答"
        return "generate_answer"

▎ 这就是路由规则——"风控通过去合规，不通过退回"。

Step 4：组装 Graph

graph = StateGraph(AgentState)

添加节点
graph.add_node("call_llm", call_llm)
graph.add_node("use_tool", use_tool)
graph.add_node("generate_answer", generate_answer)

添加边
graph.add_edge(START, "call_llm")              # 入口 → LLM思考
graph.add_conditional_edges("call_llm", should_use_tool)  # LLM → 工具 or 回答
graph.add_edge("use_tool", "call_llm")          # 工具结果 → 回 LLM 继续思考
graph.add_edge("generate_answer", END)          # 回答 → 结束

agent = graph.compile()

▎ 组装完毕。这就是一个最基础的 ReAct Agent（思考→行动→观察→再思考的循环）。

-**State**：State 是 LangGraph 中保存运行信息的共享数据结构，每个节点都会读写它；通过 reducers，新的修改可以和旧数据合并，而不是简单覆盖。
-**Nodes**：可以被视为函数/工具，处理数据并且返回结果
-**Edges**：Edges 是 LangGraph 中连接 nodes 的路线规则，用来决定当前 node 执行完之后，下一个运行哪个 node。（编排路径）

1. 对于State（State 就是一个 Python 字典）来说，messages是必填的么；额外字段都有哪些可填的（什么情况下需要设置额外字段）
	额外字段专门存储关键信息，Node 能直接读取
2. Node 就是一个函数：接收 State → 做点事 → 返回 State 的更新。调 LLM 的 Node是必装的。**能装哪些node呢（agent能做哪些事情）**


state就是菜的现状，node就是做菜的步骤，edge就是不同步骤之间的顺序
 
 ReAct 模式下 LLM 自己决定顺序，你只需要写"有 tool_calls就继续"这一条规则
 尽量让 LLM 自主决策，你只管兜底（设上限、加审批）
 对于react模式下state、node、edge的判断，就要好好想想哪些是LLM能做到的，哪些是LLM做不到的

关于messages的想法是这样子的：
messages包含humanmessage、AImessage、Toolmessage；
所以这个场景中可能有的字段：订单号—Humanmessage、商品信息—Toolmessage、退款规则—Toolmessage、人工确认的结果—Humanmessage
