关于多skills命中率下降和token消耗量上升的问题
两个问题：
1. 所有 skill 的定义（名字+描述）在对话一开始就**全量塞进 context**——skill 越多，占的 token 越多
2. 模型在几十上百个相似选项里越容易选错/漏选
	1. description 没写清"什么时候该用",模型不知道该触发（如果几个skills的description很相似呢，这时候Claude选择调用什么呢）
	2. skill 太多选择困难

我的想法：
1. 要对skills构建路由，在路由的辅助下统一分配；
2. 要构建完整的工作流程，确定哪些skills在哪些环节起作用，将他们分门别类起来，方便AI进行判断

搜集到的方法：现在的方法大多很原始，而且实践效果不好。我看到的比较好的方法：
1. 优化 skill 描述和触发 eval
2. Tool Retrieval / RAG Router langgraph数据库的构建（langgraph的学习）

关于skill name/description 优化指南的信息：
1. description 写得越 **pushy** 越好
2. 用 `Do NOT use when` **负向边界**划清地盘
3. 控制长度别超**全局字符预算**
4. 官方 `skill-creator`自带测试脚本，可检测触发率
