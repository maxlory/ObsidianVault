一、
https://alexop.dev/posts/stop-bloating-your-claude-md-progressive-disclosure-ai-coding-tools/
有效经验：
	Claude.md的问题在于：在要求沉淀失败经验后，Claude会将每一次失败的问题都沉淀在Claude.md中。这导致Claude.md的长度不断拉长，且其中的内容往往是大量琐碎的经验片段。
	当面对大量的Claude.md文本时，Claude不会选择或者说，不会完整理解其中的内容。这导致大量沉淀在Claude.md中的经验是完全无用的。
	‘HumanLayer keeps their CLAUDE.md under 60 lines.[3](https://alexop.dev/posts/stop-bloating-your-claude-md-progressive-disclosure-ai-coding-tools/#user-content-fn-2) Frontier LLMs reliably follow 150-200 instructions—and Claude Code’s system prompt already uses about 50 of those.[3](https://alexop.dev/posts/stop-bloating-your-claude-md-progressive-disclosure-ai-coding-tools/#user-content-fn-2)’
	文章指出前沿的 LLM 的系统文档通常需要 150 到 200 条指令——而 Claude Code 的系统提示语就已经占用了其中大约 50 条指令。
	这意味着我们只有100行左右的空间实现Claude.md的构建。过长的系统文档完全起不到作用。
推荐方法：
1. “背压机制”——即一种自动化的反馈机制，能够让智能体自行进行修正。可以设计关于代码风格、格式、类型的脚本，让AI在生成代码后直接跑一遍。
   跑失败了，说明代码一定是有问题的
   跑成功了，说明代码通过了基础自动化检查。虽然不能代表完全正确，但是基础的错误已经被排除了
2. 创建 /learn skill，将发现的问题、可沉淀的工作流都整理出来。通过 /docs 保存这些知识。沉淀的经验都保存在文件夹中，CLAUDE.md 只是告诉 Claude 该去哪里查找信息。
收集的信息：/learn + 作者的Claude.md

二、
https://docs.bswen.com/blog/2026-03-20-claude-md-compliance-degradation/
有效经验：
	位于顶层的规则能够得到有效执行。而位于底层的规则则被忽视或被赋予较低的优先级。这不是特殊而是普遍的现象
	大型语言模型在处理文本时，会更重视文本开头部分的内容，而相对忽略文本末尾的内容。这种现象被称为“位置偏差”，也是 Transformer 架构的一个根本性局限
	相关解释：
		1. 注意力机制的局限性：Transformer 模型利用注意力机制来衡量不同单词的重要性。前面的单词会影响到后面单词的理解方式，这就使得模型在处理文本时，不可避免地会偏向于文本的开头部分。
		2. 注意力分配能力有限：注意力机制在处理长序列时，无法始终保持对所有元素的同等关注。随着上下文规模的增加，模型不得不分散注意力，而较早出现的内容往往会被赋予更高的权重。
解决方法：
	渐进式信息披露架构（真实目录结构树）

	可以看到CLAUDE.md的内容只有50～80行左右
	其他内容都是以skill的形式按需触发
常见错误：
	1. 新的经验被沉淀到CLAUDE.md中，可是没有及时优化CLAUDE.md
	2. 显而易见的废话没必要记录
	3. 没有必要解释，相信Claude的能力。注重规则而不是解释
	4. 在CLAUDE.md中的多个部分重复内容
