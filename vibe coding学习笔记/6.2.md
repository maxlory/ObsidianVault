**消息**
在LangChain中，发送给LLM的消息、LLM返回的消息都统一被封装BaseMessage，它是Agent中基本的上下文单元。
在LangChain中，我们并不需要自己创建BaseMessage对象，LangChain已经把常见消息根据角色（Role）创建了
对应的BaseMessage的子类：
• SystemMessage: role是system，代表系统消息，用于设定模型角色和交互背景（系统提示词）
• HumanMessage: role是user，代表用户输入的消息（用户输入）
• AlMessage: role是assistant，代表LLM生成的响应，包含：文本、工具调用、元数据（AI回复）
• ToolMessage: role是tool，代表工具调用时产生的结果
我们可以直接使用这些Messages类型来发送消息。

from langchain.agents import create_agent
from langchain.tools import tool
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage

#定义工具
@tool
def get_weather(location: str) -> str:
"""
	Get the weather in a given location.
	Args:
	location: city name or coordinates
"""
	return f"Current weather in {location} is sunny!"

#创建 Agent
Agent = create_agent(
	model="deepseek:deepseek-chat",
	tools=[get_weather],
	system_prompt="你是一个热心的 AI 助手。",
)

#调用 Agent，发送信息
response = Agent.invoke({
	'messages':[
	{'role':'system','content':'你是一个友好的AI助手'},
	{'role':'user','content':'你好'}
	]
})
#response是一个字典，内容是消息列表。messages是字典的key，列表是字典的value
#整体是字典和列表的多层嵌套。最外层的response是字典，这个字典的value是列表，列表中的值是字典

response = Agent.invoke({
	'messages':[
	SystemMessage('你是一个友好的助手'),
	HumanMessage('今天北京的天气怎么样？')
	]
})
#xxxxMessage取代的是字典嵌套下的列表嵌套下的值，即role和content两部分的内容 
#print(response["messages"][-1].content)

for message in response['messages']:
	message.pretty_print()

**系统提示词**
一般来说，系统提示词（System Prompt）会包含以下几个部分，通常按此顺序排列：
•身份角色（Identity）：描述AI的职责、沟通风格和总体目标。
•指令说明（Instructions）：请指导模型如何生成所需的响应。它应该遵循哪些规则？模型应该做什么，以及模型绝对不能做什么？
•对话示例（Examples）：提供可能的输入示例，以及，模型期望的输出。（效果最好）
•背景信息（Context）：向模型提供生成响应所需的任何额外信息，例如RAG的额外知识库数据，或您认为特别相关的任何其他数据。

在编写System Prompt时，可以使用**Markdown格式和XML标签**的组合来帮助模型理解提示和上下文数据的逻辑边界。
•Markdown的标题和列表有助于标记提示的不同部分，并向模型传达层级结构。它们还可以提高开发过程中提示的可读性。
• XML 标签可以帮助明确区分一段内容（例如用作参考的辅助文档）的起始和结束位置。

system_prompt = '''
＃身份
- 你是一个编程助手，你帮助用户编写Python代码。
＃指令
- 定义变量时，使用snake case命名法，而不是camel case命名法。
- 不要返回markdown格式说明，仅仅返回代码即可。
'''
#定义了一个系统提示词的变量，就不用在后续创建Agent的时候再定义

Agent = create_agent(
	model = 'deepseek-chat',
	system_prompt = system_prompt
)


**工具**
工具的本质就是函数，但是要让Agent认识这个函数是个工具
1. 使用tool修饰器将普通python函数包装成Agent可以识别和使用的工具
from langchain_core.tools import tool

@tool(name = 'get_weather', description='get the weather of the given city')
#装饰器主要有两个参数：name+description
def tool1(city: str) -> str:
	return f'The weather of {city} is sunny!'
#装饰器：把一个普通python函数包装成Agent可以识别和使用的工具

2. 使用函数名和文档注释描述工具
工具名：默认就是函数名
工具所需的参数：默认是函数的参数列表
工具作用的描述：默认是函数的注释
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
	'''
	get the weather of the given city
	'''
	return f'The weather of {city} is sunny!'

#不用 @tool 也可能能用，但用了 @tool 更标准、更清晰、更可控。
