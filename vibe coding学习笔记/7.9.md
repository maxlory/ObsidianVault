### Claude Code 五层架构
0. LLM 是底座计算核心，相当于 CPU + Runtime，负责推理与控制循环（agentic loop）。
1. 第一层 Tool Layer 是最底层的执行接口层，类似操作系统的 syscall 或基础设施 API，定义“系统可调用的原子能力”。
2. 第二层 Knowledge Layer 是策略与操作规约层，Skills 本质是结构化 SOP 注入机制，解决“在什么上下文中，以什么步骤调用哪些工具”。
3. 第三层 Agent Layer 是执行编排层，SubAgents 提供隔离执行单元，Agent Teams 提供多单元协作拓扑，解决复杂任务拆解与职责分离。
4. 第四层 Automation Layer 是事件驱动控制层，Hooks 像 middleware 或 pipeline 拦截器，在关键节点注入自动化校验与约束逻辑。
5. 第五层 Distribution Layer 是能力封装与交付层，Plugins 将前述能力模块化、版本化，实现跨项目与跨组织复用。
注意：这是一个**架构理解模型**，不是运行时真实存在的五层调用栈。很多层之间会互相交叉。
用户请求
    ↓
加载上下文（Knowledge Layer：CLAUDE.md、Skills等）
    ↓
Agent决定是否拆分任务（Agent Layer）
    ↓
调用具体工具（Tool Layer）
    ↓
Hooks在关键节点自动检查/拦截（Automation Layer，可在调用前后触发）
    ↓
返回结果


#### Skills 在系统中呈现出三种结构
1. 向下，它通过 <font color="#92d050">allowed-tools 和 scripts/ 对 Tools 进行约束与编排</font>（分别通过SKIl.md中的frontmatter和script实现），本质上是用知识来规范行动边界，相当于“知识约束行动”。
2. 向上，它<font color="#92d050">为 SubAgents 提供预加载的专业知识</font>，使子代理在决策前就具备特定领域能力，本质上是“知识服务决策”。
3. 在平行维度上，Skills 与 CLAUDE.md 形成互补关系：Skills 是**按需加载**的专业知识模块，而 CLAUDE.md 是**常驻**的通识背景，两者分别承担“专业能力增强”和“基础认知框架”的角色。（如果 Skills 被设计成“全量加载”而非“按需加载”—— Skills 就退化成了 CLAUDE.md 的一部分。==渐进式披露不是“省 token 的技巧”，而是知识层架构的必然要求==）

### Skills 架构的哲学意义——与现实的映射（从 SOP 到组织智能）
Skills的复杂演进路径映射到企业的知识管理成熟度
第一级是标准操作程序，得到标准执行流程（SOP）处理一般情况
第二级是专家系统，处理复杂情况
第三级是组织智能，处理多流水线复杂情况
总结：==从一个人照章执行，到一个专家应对复杂情况，再到一个团队协作完成系统级任务——每往上一级，系统面对的不确定性和协作复杂度都会跃迁==。
![[Pasted image 20260709110828.png]]
具体来说：
1. 第一级是 SOP 阶段。一个单一 SKILL.md，把流程写清楚，步骤可复现，行为可预测。
2. 第二级专家系统阶段。在单一流程之上引入知识库、模板、脚本和权限控制，能够处理同一领域的各种复杂和边界情况。一个 Skill 通过渐进式披露组织丰富的领域知识，配合脚本和模板，成为完整的领域能力包。
3. 第三级上升到组织智能。多个 Skills 与 SubAgents 配合——分析子代理加载分析 Skill、审查子代理加载审查 Skill、测试子代理加载测试 Skill——形成流水线式的团队协作。加上 Hooks 的自动化质量控制和 Plugin 的打包分发，就构成了完整的“组织智能”。
**哲学意义**：它不仅仅是节省 token 或给 Claude 一份参考。Skills 是把人类组织中积累了几十年的知识管理经验——SOP、专家系统、组织学习——技术化映射到 AI Agent 架构中。

### Skill 设计的四种模式
模板驱动｜脚本增强｜工具隔离｜知识分层

1. 模板驱动：==附件只有模板==——用模板强约束输出结构，让结果稳定、可对比、可自动解析
	适用范围：<font color="#92d050">适用于报告生成、文档输出等需要格式一致性的场景</font>。解决的是“输出不稳定”的问题，本质是把自然语言生成转化为结构化接口。
	![[Pasted image 20260709113951.png]]

2. 脚本增强：附件只有脚本——把计算、匹配、数据转换等确定性逻辑交给脚本执行，拒绝让 Claude 推理完成
	适用范围：<font color="#92d050">公式计算、正则匹配、指标统计等场景</font>——解决的是“结果不稳定”的问题，本质是把概率型推理替换为确定性执行。
	是否适用脚本的判断原则：如果你在 SKILL.md 里开始写公式，让 Claude 去计算或反复推理数值结果，那就应该停下来思考——这种<u>确定性计算应当下沉到脚本中完成。Claude 负责判断和理解，脚本负责计算和执行</u>。
	**重点**：
	1. <mark style="background:#d3f8b6"> 脚本不应依赖额外的外部安装环境</mark>（例如运行时需要再执行 pip install），优先使用标准库，若确有依赖必要，须在说明文档中明确声明；
	2. <mark style="background:#d3f8b6">脚本不应包含交互式输入，必须是一次性可执行、无人工干预的流程</mark>；
	3. 同时也不要把所有逻辑都塞进脚本，只有确定性、可计算、可验证的逻辑才适合放入脚本，涉及判断、语义理解或策略决策的部分应保留给 Claude 处理。

3. 知识分层：附件只有reference和examples——按使用频率组织知识，高频内联、中低频按需加载（渐进式加载解决上下文膨胀问题）

4. 工具隔离：在frontmatter中通过 allowed-tools 明确能力边界，限制 Skill 可以调用的工具
