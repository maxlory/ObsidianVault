以视频制作的形式演示Harness的具体工作情况（可以后续的PPT功能全部由网页实现）
成熟的Harness应该包含什么
1. 上下文管理：模型收到的上下文是什么
	1. skill 通过文件把上下文变成可重新读取的状态。**每一部分的上下文以文件（md）的形式存放，而不是整个放在一起**
	2. skill中给出了各阶段文件读取的指南，在不同阶段读取不同的内容（总分）
	3. 如何使用subagent实现并行任务，这个skill给出了一定的解答（因为subagent看不到完整的主线上下文，所以要求主agent 把sub-agent完成所需任务的上下文打包给它。 ）
2. 工具系统：模型能够使用什么工具，从而实现什么功能
	当多个subagent进行开发并且修改文件的时候，是如何避免这些agent产生冲突
	1. 每个subagent只完成自己的任务，自己的任务和别人的任务是分离的
	2. 如果有必须所有subagent同时修改的文件，让主线agent完成
	3. 让所有subagent使用同一套要求，避免冲突
3. 执行编排：模型按照怎样的步骤实现
	不同步骤之间的编排是如何实现的：首先，Harness的能力是agent自带的，并不是skill提供的；其次，Harness本身并没有进行编排的能力，这种能力是skill提供的指导。
	**Harness 提供“能编排”的运行底座；skill 提供“该如何编排这个任务”的流程约束。**
	**将checkpoint早早地安排在整个项目流程的前面**。早点形成可复用、较满意的模板，避免问题的积累
4. 状态与记忆：系统如何跨步骤保持连续性
	1. outline是如何实现的重要细节的记录的，又是如何让agent知道的。**outline的存在很重要**。随着程序的进行，原来的上下文已经遗失了。而且在项目进行中，已经生成的内容和需要修改的内容作为上下文内容太多了。额外配置一个新的文件，并且在checkpoint进行记录，能够将重点内容及时记录下来，方便使用者对整个项目的把控和后续程序实现的上下文理解
5. 评估与观测：系统怎么知道自己做的对不对
	自检—修复—再汇报
	自检的三种执行方式：
	1. **agent teams**：有更强的角色隔离、任务边界、可能还有独立上下文和结果汇总机制。（**重点是“隔离 + 编排”**）
	2. subagent：主 agent 手动拉一个临时助手
	3. 当前agent自检
6. 约束与恢复：出错了怎么办，怎么避免跑偏
	如何让AI在大部分情况下做对，但是小部分有问题的背景下，只修改小部分内容：将整个节点的结构彻底拆分成最小单位，根据用户的需求，只修改这些最小单位
