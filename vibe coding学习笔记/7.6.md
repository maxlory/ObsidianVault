## 关于skill的相关学习

### 一、关于skill的第一性原理
Tools （能做什么）是行动原语。它回答的是能做什么。读文件、改代码、执行 Bash 命令……这些是操作层面的能力，类似人的双手。
SubAgents （谁来做）是执行分工。它回答的是谁来做。当任务复杂到需要独立上下文时，子代理承担专职职责，类似团队中的同事。
Hooks （自动化流程）是流程规则。它回答的是什么时候检查。它们在关键节点自动触发质量校验或合规约束，类似企业中的质检流程。
而 Skills （怎么做）回答的，是另外一个非常关键的问题：“怎么做，以及何时做”，它不是工具，也不是分工机制。它是一种可操作知识结构。
重点：<font color="#92d050">整个Claude code的工程体系是仿照现实企业的SOP体系实现的。或者说AI的一切都是对现实世界已有规则的映射</font>

### 二、Skill 触发机制
skill是如何触发的：同一个 Skill 既可以作为斜杠命令使用，也可以让 Claude 自动判断何时需要。
skill的自动触发：<mark style="background:#d3f8b6">Claude 读取所有 Skills 的<u> description</u>，通过语义理解判断当前对话是否匹配某个 Skill。——>description是skills是否被触发的关键</mark><u></u>
skill的主动触发：<mark style="background:#d3f8b6">当用户手动触发skill的时候，Claude会跳过description的触发，直接加载skill全文</mark>

==三种方式控制 Claude 对 Skills 的访问==：
1. 全局禁用：在  /permissions  中 deny Skill  
2. 工具精确控制：Skill(commit)  精确匹配，Skill(deploy *)  
3. 前缀匹配逐个控制：给 Skill 加  disable-model-invocation: true frontmatter

### 好的skill设计：

SKILL.md                    ← 导航页：概述 + 引用（< 500 行）
├── reference.md            ← 详情页：详细 API 文档
├── examples.md             ← 详情页：使用示例
└── scripts/validate.sh     ← 工具：可执行脚本

注意：==SKILL.md 应该被控制在 500 行以内==。如果过于复杂，应该将详细参考资料移到独立文件，并在 SKILL.md 中进行引用（也就是我们所常说的渐进式加载）。

#### 结构拆解：
YAML frontmatter，是通过---包裹的元数据：包含name+description
Markdown正文：是技能的具体说明
辅助文件：.claude/skills//SKILL.md——每个 Skill 在自己的目录中，可以包含辅助文件（此处只有主文件，下一讲中的示例我们将看到辅助文件）。

重点：description 是 Skill 的灵魂，是claude能否调用skill的唯一保证
