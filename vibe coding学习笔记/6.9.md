Plan-and-Execute模式： planner → agent ⇄ replan → END
planner：调 LLM，把用户问题拆成步骤列表
agent：拿 plan[0]（第一步）去执行（内部其实是一个 ReAct agent）
replan： 调 LLM，看已完成的步骤，决定更新计划还是直接给最终回答
总结：
1. planner 和 replan 是纯思考型 LLM 调用：只给 prompt，不调用工具
（我应该把每一个部件是什么结构，能够包含什么东西，都了解清楚
不是说学会语法，而是知道为什么）
2. planner、agent、replan三个node是Plan-and-Execute模式的模版，核心是先计划再执行。我发现基础的node模板几乎都调用了LLM，需要额外添加的node都没有调用LLM（或者反过来说，是因为LLM做不到所以才需要添加额外的node）
	不完全正确，但是方向是对的，需要额外补充： 
	额外 Node 的添加原因有两种：
▎ 1. LLM 做不到 → human_approval、logger、formatter（不调 LLM）
▎ 2. 需要 LLM 换个角色 → reviewer、summarizer（调 LLM，但 prompt 不同）


Plan-and-Execute模式的常见需求：（**计划执行**）
1.  planner 只在最开头跑一次：计划只需要制定一次。后续调整计划是 replan 的事。而且，replan 的 prompt 里已经包含了“原始计划”
2. replan 的输出只有两种可能：填了 response（所有步骤完成，可以回答用户了）或更新了 plan（还有步骤要做）。所以只需要看 response 字段有没有值


Human-in-the-Loop（加一个人工介入的node）（路径随机性较强—也就是需要人工规划路径的时候用）（**人工介入**）
解决什么问题：有些操作 LLM 不该单独决定——发邮件、退款、删数据、发布内容。
不用它会怎样：LLM 自作主张执行了不可逆操作。
场景特征：流程中有"做错了代价很高"的步骤。
怎么搭配：不是独立模式，是加在 ReAct 或 Plan-and-Execute 上的。在危险操作的 Node 前面插一个 human_approval Node。
现在的问题是：人工介入的节点是在危险操作前还是后，如果在后还有意义么

Reflection / Self-Critique（加一个反思node）（**反思**）
解决什么问题：LLM 一次生成的质量不够好——漏了要点、格式不对、逻辑有漏洞。
不用它会怎样：输出质量不稳定，全靠 LLM 一次运气。
场景特征：**输出有明确的质量标准可以检查**（比如"报告必须包含 5 个板块""代码必须通过测试"）。
怎么搭配：在输出 Node 后面加一个 reviewer Node（用 LLM 换个角色审查），不合格就打回重做。本质是一个 generator ⇄ reviewer 的循环。

Multi-Agent / Supervisor（由一个Supervisor作为调度node，其他agent在调度下进行分工）（**多智能体**）
解决什么问题：一个 LLM 的 prompt 装不下所有专业知识。比如一个 agent 要同时懂财务分析、法律合规、技术尽调——prompt 太长，角色太杂，LLM 表现下降。
不用它会怎样：一个 LLM 身兼多职，每个方向都做得半吊子。
场景特征：任务需要多个专业角色，每个角色有独立的工具和 prompt。
怎么搭配：Supervisor 是一个调度 Node，决定把任务分给哪个 worker agent。每个 worker 内部可以是 ReAct。

Map-Reduce（把一个完整的任务拆成多部分，然后并行处理）（处理流程类似，不同的话使用Multi-Agent）（**并行子任务**）
解决什么问题：有 N 个独立子任务，一个一个串行做太慢。
不用它会怎样：能跑，但慢。比如分析 10 家公司的财报，串行要 10 倍时间。
场景特征：多个子任务互相独立，可以并行，最后需要汇总。
怎么搭配：Map 阶段把任务拆成 N 份并行处理（每份可以是 ReAct），Reduce 阶段用一个 Node 汇总所有结果。

注意：既然分子任务工作，必然在子任务工作前有任务分发节点（send）。在各子任务完成工作后，必然有reducer环节（reducer可以作为一个node，但是reducer本身是字段的合并规则，这两点要区分）
send分发节点不是LLM，而是纯粹的代码（为什么这部分不用LLM实现）

Subgraph
解决什么问题：Graph 太复杂，Node 太多，不好维护。
不用它会怎样：所有 Node 挤在一个 Graph 里，改一个地方可能影响其他地方。
场景特征：Graph 中有一部分逻辑可以独立封装、在多个地方复用。
怎么搭配：把一段子流程封装成 Subgraph，在主 Graph 里当一个 Node 来用。Plan-and-Execute 里的 agent 其实就是一个 Subgraph（内部是完整的 ReAct）。
