## C. 笔记之间的矛盾

### 矛盾 1（最严重）：`~/.claude/skills/deep-research/` 到底会不会被覆盖
- **03-skills.md:11 / :613 / :685** 说：`full` 和 `research` profile 会把用户的 `deep-research/SKILL.md` **无备份直接写掉、不可恢复**，并建议「装之前先备份或改名」。
- **06-install-isolation.md:481-497** 说：skills 有两级保护，目录已存在且不在 install-state 里 → **整个 skill 的所有操作被跳过**并打印警告。
- **代码判定：06 对，03 错。**
  - `scripts/lib/install/claude-skill-migration.js:271-283` `classifySkillGroup`：
    `if (pathExists(flatSkillRoot) && !hasManagedFlatFile)` → 该 skill 全部 operation 进 `skippedOperations`。
    `flatSkillRoot = <targetRoot>/skills/<skillName>`（`:100`）。
  - 首次安装时 install-state 为空 → `hasManagedFlatFile === false` → 用户已有的 `deep-research/` 目录整组跳过。
  - 生效范围：`CLAUDE_TARGETS = {'claude','claude-project'}`（`:9`），正好覆盖 03 讨论的 `--target claude`。
- **03 为什么会错**：它用 `install-plan.js --json` 的输出做判断，那里的 operation 是粗粒度 `copy-path`
  （实测：`{"kind":"copy-path","sourceRelativePath":"skills/deep-research","destinationPath":"~/.claude/skills/deep-research"}`），
  **保护逻辑不在 planner 里**，只在 apply 阶段跑（`scripts/lib/install/apply.js:148/165` 调 `prepareClaudeSkillMigration`）。
  planner 展开成 file 级是 `install-executor.js:641-692 materializeScaffoldOperation` 干的。
- 后果：03 给了一条不必要的「先备份 deep-research」操作建议，并把「唯一硬撞名」渲染成不可恢复损失。
  真实情况是：deep-research 会被**整组跳过**，用户的版本原样保留，ECC 那份根本装不进来。
