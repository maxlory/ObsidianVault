## 3. install-profiles.json：官方 7 个档位与它们的真实体积

出处：`ECC/manifests/install-profiles.json`

我按 manifest 解析依赖后实测的每档体积（方法见下方代码块）：

| profile | 声明模块数 | 解析后 | **skill 数** | 常驻 metadata≈ | 占 200K 窗口 | 全文体积 |
|---|---|---|---|---|---|---|
| `opencode` | 3 | 4 | 44 | ~6.8K tok | 3.4% | 93K tok |
| **`minimal`** | 5 | 6 | **44** | ~11.1K tok | 5.6% | 93K tok |
| `core` | 6 | 7 | 44 | ~11.1K tok | 5.6% | 93K tok |
| `security` | 7 | 8 | 63 | ~12.3K tok | 6.1% | 132K tok |
| `research` | 9 | 10 | 70 | ~12.9K tok | 6.4% | 126K tok |
| `developer` | 9 | 10 | 121 | ~15.6K tok | 7.8% | 324K tok |
| **`full`** | 25 | 25 | **280** | **~25.7K tok** | **12.9%** | 618K tok |

两条 profile 描述里作者的原话（这是取舍表态，不是我总结的）：

> `minimal`: "Low-context Claude Code setup with rules, agents, commands, platform configs, and quality workflow support, **but no hook runtime**."
> `opencode`: "Default OpenCode setup ... It **intentionally excludes** `hooks-runtime`; opt in with `--modules hooks-runtime`."

> 🔑 作者的默认 OpenCode 档和 minimal 档**都主动不装 hooks**。对照 ECC 有 48 个 hook 脚本——这是"hook 是可选负担而非核心价值"的官方表态。

README 也印证：非 Claude 的 11 个 harness（Cursor / Gemini / Zed / Antigravity / Qwen / Hermes / OpenClaw / Kimi / CodeBuddy / JoyCode）**清一色推荐 `--profile minimal`**，只有 OpenCode 用 full（`README.md:255-265`）。Claude 手动安装的示例命令也是 `./install.sh --profile minimal --target claude`（`README.md:288`），紧跟一句 "This profile intentionally excludes `hooks-runtime`."（`README.md:298`）。

**上下文数字的口径说明（重要）**：
"常驻 metadata" = 所有 skill/agent/command 的 `name + description` 之和 ÷ 4 字符/token。这是 Claude Code 为了做发现（discovery）**必须常驻**的部分，跟你用不用它无关。全量安装实测：

```
skills   281 个  name+desc 68,337 字符 ≈ 17.1K tok
agents    67 个  name+desc 14,904 字符 ≈  3.7K tok
commands  94 个  name+desc 11,312 字符 ≈  2.8K tok
合计 ≈ 23.6K tok = 200K 窗口的 11.8%
```

⚠️ 置信度：**中（~65%）**。这是静态估算，不是实测 `/context` 读数。分词器实际比 4 字符/token 略密，且 Claude Code 具体注入哪些字段我没有实测验证。[[解剖03 Skills 体系]] 用另一种口径算出 skill 部分 23.3K tok，比我高——两者都落在 **11%~13% 的量级**上，结论不变。
你可以自己验证的动作：装完之后在 Claude Code 里跑 `/context`，看 "System prompt + tools" 那一行的实际数字。

叠加参考：作者在长文里说 Claude Code 自己的系统提示词就占 ~18K tok（约 9%）。**全装 ECC + Claude Code 基线 ≈ 40K+ tok，还没开始干活就吃掉 20%。**

<a id="4"></a>
## 4. 🔑 两条安装路径体积差 6 倍——plugin 路径是最大化的那条

这是本渠道最实用的一个发现，仓库里没有任何地方明说，但 manifest 一对比就出来了。

`ECC/.claude-plugin/plugin.json`：
```json
"skills":   ["./skills/"],
"commands": ["./commands/"],
"mcpServers": {}
```

> 🔑 **plugin 安装没有任何选择性——`./skills/` 是整个目录，281 个全进。**
> 而 README 的 "Recommended default" 恰恰是 plugin 路径（`README.md:140`：install the Claude Code plugin for Claude Code）。

对比：

| 路径 | skill 数 | 常驻 metadata | 能不能选 |
|---|---|---|---|
| `/plugin install ecc@ecc`（README 首推） | **281** | ~23.6K tok | ❌ 不能 |
| `./install.sh --profile minimal --target claude` | 44 | ~11K tok | ✅ 能 |

也就是说：**最方便的那条路 = 体积最大的那条路**。作者自己的 minimal profile 存在，但默认推荐的路径绕开了它。

配套坑（作者自己在 README 里承认的）：
- `README.md:140`：**"Do not stack install methods."** 同一个 harness 装两次会重复 skill/命令/hook/配置。
- `README.md:163`：**"If you install the plugin, do not run `./install.sh --profile full` afterward."**
- `README.md:1863`（Troubleshooting "ECC appears twice or hooks fire twice"）：**"The usual cause is installing the Claude plugin and then running `install.sh --profile full`..."**
- `README.md:1815`：不要往 `plugin.json` 加 `"hooks"` 字段，Claude Code v2.1+ 会自动加载，显式声明触发 duplicate 报错——附三个真实 issue：[#29](https://github.com/affaan-m/ECC/issues/29)、[#52](https://github.com/affaan-m/ECC/issues/52)、[#103](https://github.com/affaan-m/ECC/issues/103)。

`skills/ecc-guide/SKILL.md:121` 也重复了这条：
> "Warn users not to stack plugin installs and full manual/profile installs unless they intentionally want duplicate surfaces."

<a id="5"></a>
## 5. MCP-CONNECTOR-POLICY：砍掉 6 个默认 MCP 的判据

出处：`ECC/docs/MCP-CONNECTOR-POLICY.md`
上游：https://github.com/affaan-m/ECC/blob/main/docs/MCP-CONNECTOR-POLICY.md
同步记在 `CHANGELOG.md` 的 `## Unreleased` 段。

**这是整个仓库里表态最硬、最具体的一份取舍文档。** 判据两条，必须同时成立才配当默认：

> 1. **Universal** — 基本上每个用 coding agent 的人、在 ECC 支持的每个 harness 上都用得着。
> 2. **MCP beats a CLI/API wrapped in a skill** — 这活儿真的需要 MCP 才有的东西：交互式会话状态、流式、auth 握手、结构化浏览。**无状态的请求/响应就该做成 skill，不是 server。**
>
> 原文关键句：*"Tool schemas load into every session; each default connector taxes every user's context window whether they use it or not."*
> 以及：*"The default set stays well under ten. In practice the 2026 field default across serious harnesses is zero to two connectors plus native built-ins."*

**现在默认只剩 1 个**：`chrome-devtools`（Google 官方 DevTools MCP，理由是"价值在于那个一直开着的会话，不是一次性命令"，且无需 key）。
仓库根目录 `.mcp.json` 实测确认：里面就一个 `chrome-devtools`。

**2026 年 6 月审计砍掉的 6 个，逐条判词**（这直接回答了"哪些被 Claude Code 原生能力取代"）：

| 被砍的默认 MCP | 判决 | 替代物 | 作者的理由（摘译） |
|---|---|---|---|
| `github` | drop for skill | `gh` CLI + `github-ops` skill | "`gh` 在每个模型的训练数据里，一次性命令 token 开销极小，`gh auth login` 认证一次就行。**这个 MCP 的 ~30 个 tool schema 对每个会话都在收税。**" |
| `context7` | drop for skill | `documentation-lookup` skill 直调 REST | "两次无状态调用 + bearer key，没有会话状态可以正当化一个 server" |
| `exa` | drop for skill | **harness 原生搜索**（Claude Code WebSearch / Codex web_search / Cursor @Web） | 还要 API key，通不过 universality 这关 |
| `memory` | **drop entirely** | **harness 原生 memory**（Claude Code 自动 memory 目录、Cursor memories、AGENTS.md）+ ECC 自己的 instinct 系统 | "**这个 knowledge-graph server 解决的是 2024 年的问题，harness 后来已经把它吸收了。**" |
| `playwright` | drop for skill | `@playwright/cli` | "**厂商自己都把 agent 工作流搬离了 MCP**——每步返回完整 accessibility tree 太烧上下文" |
| `sequential-thinking` | **drop entirely** | **各家 harness 原生的 extended thinking** | "这个 server 没有包装任何外部系统——**一个打扮成 connector 的 prompting 套路**" |

六个全部保留为 opt-in（在 `mcp-configs/mcp-servers.json` 里），并提供 `ECC_DISABLED_MCPS` 环境变量过滤。

> 🔑 这份文档的判据可以**直接搬来判断 ECC 自己的 skill**：一个 skill 如果只是把 Claude 已经会的事写成 markdown，它就是 `sequential-thinking` 的同类。

## 6. agent-sort：官方自带的"该留什么"决策工具

出处：`ECC/skills/agent-sort/SKILL.md`

这个 skill 的 description 是整份仓库里最直白的一句自认：

> **"Use when ECC should be trimmed to what a project actually needs instead of loading the full bundle."**

正文里的 When to Use 第一条：

> **"A project only needs a subset of ECC and full installs are too noisy"**

它的方法论（可以直接拿来用）：
- 只用两个桶：`DAILY`（每个会话都该加载）和 `LIBRARY`（保留可达但不默认加载）。**"LIBRARY does not mean delete; it means keep accessible without loading by default."**
- 硬规则：**"Every DAILY decision must cite concrete repo evidence"**——靠 `rg --files`、`package.json`、`go.mod` 这类仓库证据分类，不靠"感觉有用"。
- 证据表格式示例（原文）：
  ```
  skills/frontend-patterns | skill | DAILY   | 84 .tsx files, next.config.ts present | core frontend stack
  skills/django-patterns   | skill | LIBRARY | no .py files, no pyproject.toml       | not active in this repo
  ```
- Handoff：接 `configure-ecc`（装）→ `skill-stocktake`（查重叠）→ `strategic-compact`（压上下文）。

**讽刺点**：`/agent-sort` 这个命令**已经被退役进 legacy-command-shims 了**（见第 9 节）。也就是说官方最该推的减肥工具，它的斜杠入口反而被下架了，只剩 skill 形态。

## 7. skill-stocktake / config-gc / context-budget：官方的三件减肥工具

三个都在 `workflow-quality` 默认模块里，说明作者认为"减肥"是默认必备能力。

### 7.1 config-gc — 判定标准最具体的一件

`ECC/skills/config-gc/SKILL.md`。设计哲学第一条就是承认问题：

> **"Append-only configs leak.** Skills, memory files, hooks, and permission entries only ever get added. Without periodic review they rot silently."

触发时机里有一条是作者自己点自己的名：

> **"After installing a large skill pack (e.g. this repo), to reconcile overlaps with existing setup"**
> Best Practices 里再说一遍：**"installing a 50-skill pack is exactly when overlap with existing skills appears."**

8 个扫描通道 + 每个通道的判废信号：

| 通道 | 判废信号 |
|---|---|
| Skills | 名字高度重叠 / 近期 transcript 里从没触发过 / 与用户实际工作领域不符 / SKILL.md 空或坏 |
| Memory | 一个话题多条索引 / 内容与更新条目矛盾 / 日期已过 / 索引里没有的孤儿文件 / <100 词的碎片 |
| Hooks | **脚本在磁盘上但没有任何 hook 配置引用它** / 被重写取代的旧版本 |
| Permissions | 重复条目 / 已被通配符覆盖的具体条目（有 `Bash(*)` 还留 `Bash(git push)`）/ 过往实验留下的一次性授权 |
| MCP servers | 连不上 / 功能重复 / 长期不用 |
| 定时任务 | 30 天前打过的一次性提醒 / 目标脚本已不存在 |
| 项目历史 | 过期 handoff 快照 |
| 运行时缓存 | 按体积+mtime 排序，>30 天且大的 |

安全纪律（值得抄）：**软删优先**（`.disabled` 改名 > 移到 `~/.claude/_gc_trash/` > 真删）、**逐条 `[y/n/skip]` 确认，禁止批量 yes**、每次跑都往 `~/.claude/gc_log.md` 记账。
反 pattern 里有一条很聪明：**"Treating 'old' as 'dead'. A skill untouched for 60 days may be seasonal."**
还有一条可以直接用来砍 ECC：**"When two skills overlap, prefer disabling the one with the weaker trigger description — it's the one that was probably never firing anyway."**

### 7.2 skill-stocktake — 5 档判决

`ECC/skills/skill-stocktake/SKILL.md`。对每个 skill 出 5 选 1 判决：`Keep` / `Improve` / `Update` / `Retire` / `Merge into [X]`。
4 条 checklist：与其他 skill 内容重叠？与 MEMORY.md/CLAUDE.md 重叠？技术引用是否过时（有 CLI flag/API 就上 WebSearch 核）？使用频率？
4 个评判维度：Actionability（有没有能立刻照做的命令/代码）、Scope fit、**Uniqueness（"value not replaceable by MEMORY.md / CLAUDE.md / another skill"）**、Currency。
明确写了 **"Evaluation is blind: the same checklist applies to all skills regardless of origin (ECC, self-authored, auto-extracted)"** —— 对自家 skill 不搞豁免。

分工：**config-gc 审"该不该存在"，skill-stocktake 审"质量够不够"，先 GC 再 stocktake。**

### 7.3 context-budget — 里面有可引用的成本经验

`ECC/skills/context-budget/SKILL.md`。Best Practices 三条（作者的经验值，非实测）：

> - **"MCP is the biggest lever: each tool schema costs ~500 tokens; a 30-tool server costs more than all your skills combined."**
> - **"Agent descriptions are loaded always: even if the agent is never invoked, its description field is present in every Task tool context."**
> - 检测阈值：agent >200 行算 heavy、description >30 词算 bloated、skill >400 行、rule >100 行、MCP server >20 tools、CLAUDE.md 合计 >300 行、MCP server 总数 >10 算 over-subscription。

⚠️ 注意：文档里那个 "16 agents / 87 MCP tools / 43,500 tokens" 的报告样例是**示意，不是实测**，别当数据引用。

⚠️ `/context-budget` 命令也**已退役**进 legacy shims。

> 🔑 **结论：不要用 `configure-ecc`。** 用 `node scripts/install-plan.js` / `install.sh --profile ...` 这条 manifest 路径。
