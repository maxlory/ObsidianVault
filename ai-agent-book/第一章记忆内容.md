现代 Agent = LLM + 上下文 + 工具

从 API 的视角看，每次调用 LLM 时的上下文由以下五个部分构成：静态前缀 + 动态消息历史
静态前缀：系统提示词 + 工具定义
动态消息历史：用户消息 + 模型回复（思考过程 + 文本内容 + 工具调用请求）+ 工具执行结果
1. 系统提示词
2. 工具定义
3. 用户信息
4. 模型回复：思考过程+文本内容+工具调用请求
5. 工具执行结果

ReAct：Reasoning + Acting（思考+行动）
模型先思考现在做什么，考虑是否调用工具
	调用工具后，观察工具返回的结果
	不调用工具，直接返回结果
想——>做——>（看——>想）——>做——>看

模型即 Agent：先进模型通过后训练（特别是强化学习）将工具调用能力内化为原生能力：何时调用工具、调哪个、传什么参数，都由模型自己决定，无需人工编排

Harness = 上下文 + 工具 + 约束 + 验证 + 纠正——上下文、工具（核心）
Agent = LLM + Harness

编排：管理LLM+工具
工作流：通过预定义的代码路径来编排 LLM 和工具的系统
优势：
1. 可以保证关键步骤不被跳过、关键方向选择遵循开发者的想法——不依赖LLM的判断
2. 安全性：单个节点的错误只会被限制在一个节点中，不会扩散到其他节点
3. 简单
劣势：
缺乏变通性，无法应对没有覆盖的情况

自主agent：具备自主规划能力
优势：
适合解决开放式问题：难以或不可能预测所需步骤数量和方向
劣势：
1. 成本更高
2. 风险更大：需要构建复杂的harness进行维护

模型即 Agen：编排上下文+工具——能做事，agent现在在这方面的能力很强
光有能做事不够，还要确保做得对、做得安全——护栏（约束、验证、纠正）

按防护位置可以分为三类：输入侧、执行侧和输出侧。
**输入侧**护栏在请求到达 Agent 之前拦截（用户的<mark style="background:#d3f8b6">输入</mark>）
相关性分类器、安全分类器、内容审核、基于规则的保护
**执行侧**护栏在<mark style="background:#d3f8b6">工具</mark>调用时验证
工具风险评级
**输出侧**护栏在响应返回用户之前检查（模型的<mark style="background:#d3f8b6">输出</mark>）
PII过滤器、输出验证
